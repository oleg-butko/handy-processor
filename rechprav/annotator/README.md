# Локальная очередь разметки

Запуск из корня проекта после `npm ci`:

```bash
npm run dev:annotator
```

Откройте напечатанный локальный адрес (обычно `http://127.0.0.1:5173/`).
Инструмент отдельный от рабочего сервера Handy Processor. Импортируйте JSONL,
скачанный во вкладке **Настройки → Экспортировать историю как JSONL файл**.
Для знакомства можно импортировать `rechprav/annotator/demo-history.jsonl` — это
только технические примеры, не реальная оценка качества.

Пустой запрос показывает частые одинаковые исходники. Запрос по слову или
последовательности соседних слов группирует найденные варианты и показывает
число записей для каждого. Расстояние 1/2 допускает столько буквенных правок
**на каждое слово** (включая перестановку соседних букв); для коротких слов
широкий поиск запрещён из-за большого числа случайных совпадений. Режим поиска
по результату или обоим полям помогает найти случаи, когда один вариант
появился только после процессора. Фильтр замен учитывает только правило
`recognition.terms-and-phrases` с исходом `changed`.
Дополнительные фильтры выбирают непроверенные/проверенные/неясные записи и
подтверждённое происхождение; это удобно для последовательной разметки очереди.

Число найденных записей — **частота кандидатов**, а не число доказанных ошибок:
`свод` и `слот` могут быть правильными в разных предложениях. Для каждого
варианта отдельно показано число уже подтверждённых человеком ошибок.
Последовательность слов должна быть соседней; поиск не распознаёт смысловые
перефразы и не доказывает, какое слово прозвучало. Сужайте запрос контекстом,
например `сняли свод`, и проверяйте отдельные записи.

Блок **Подтверждённые повторы** ранжирует точные пары «исходник → проверенный
текст» по числу размеченных записей. Для каждой пары показано, сколько раз
результат процессора точно совпал с эталоном, остался исходником или дал другой
текст, а также происхождение записей. Показываются 30 самых частых пар.
Учитываются все проверенные записи, включая технические и с ещё не
подтверждённым происхождением; чисел качества реального ASR из этой сводки
выводить нельзя. Нажатие на пару открывает одну её запись.

Карточка показывает исходник, результат, доступный сохранённый контекст
редактора и раскрываемую диагностику правил. Полный текст окружающего документа
в JSONL-истории не сохраняется.

Выберите запись и явно подтвердите один из исходов:

- **Исходник верен** — эталон равен исходному тексту;
- **Подтвердить правку** — эталон берётся из поля «Правильный текст»;
- **Неясно** — эталон не задан, запись нельзя оценивать без дополнительной проверки.

Отдельно подтвердите происхождение: реальное распознавание Handy, технический
пример или другой текст. По умолчанию оно **не подтверждено**, даже для внешнего
ввода: поле `source` истории не доказывает происхождение от ASR. Пустое поле
«Группа похожих фраз» оставляет автоматическую группировку одинаковых исходников
для будущего корпуса. Чтобы связать разные варианты, впишите одинаковое имя
группы; кнопка применения группе назначает его всем записям текущего варианта,
не распространяя эталонный текст или происхождение.

Правка поля сначала создаёт черновик и снимает прежнее подтверждение. Изменения
хранятся в памяти вкладки. Кнопка **Сохранить проект JSONL** скачивает все записи
истории вместе с разметкой; **Открыть проект** восстанавливает её. Проверьте,
что файл действительно сохранился, прежде чем закрывать вкладку. Браузер не
сообщает странице, записан ли файл на диск, поэтому предупреждение
при закрытии вкладки остаётся даже после нажатия кнопки скачивания. Проект может
содержать личный текст, не добавляйте его в Git; для приватных данных есть
игнорируемый каталог `rechprav/data/private/`. Размер одного импортируемого
файла ограничен 100 МиБ и 100 000 записей.

Формат строки проекта — схема 2: `history` содержит исходную запись,
`annotation` — `status`, `gold`, `note`, `originKind`, `groupId` и при наличии
черновика `draftGold`. Проекты схемы 1 также открываются; их происхождение
остаётся неподтверждённым. Сам проект не является
[корпусом для benchmark](../../docs/rechprav/corpus-format.md).

Для построения корпуса из подтверждённых записей сначала сохраните проект,
затем запустите из корня проекта (выходной каталог должен быть новым):

```bash
mkdir -p rechprav/data/private
/home/user1/.local/bin/cargo run --manifest-path rechprav/Cargo.toml --locked --offline -- \
  import-annotations rechprav/data/private/my-project.jsonl \
  --output-dir rechprav/data/private/my-corpus-001
```

Команда создаёт `report.json` и при наличии подходящих записей отдельные
`corpus-real-asr.jsonl` и `corpus-synthetic.jsonl`. Она берёт только явно
подтверждённые записи с указанным происхождением, сама вычисляет диапазоны
лексических правок через Rust-токенизатор и проверяет каждый результат
валидатором корпуса. Неподдерживаемые изменения, например пунктуация или чистая
вставка, перечисляются по ID в `report.json` и не попадают в корпус. Результат
процессора Handy не служит эталоном. Совпадающие после нормализации source/gold и вручную связанные
варианты получают общий `group_id`; `split` остаётся `unassigned`. Корпуса
реального ASR и технических примеров не смешиваются в одном файле.
После проверки отчёта можно выполнить:

```bash
/home/user1/.local/bin/cargo run --manifest-path rechprav/Cargo.toml --locked --offline -- \
  validate rechprav/data/private/my-corpus-001/corpus-real-asr.jsonl
```

Если файла реального ASR ещё нет, сначала работайте с техническим корпусом.
Для примера есть `rechprav/data/fixtures/annotation-project/project.jsonl`.
Рабочие файлы в `rechprav/data/private/` исключены из Git. После ручной проверки
групп один корпус можно разделить целыми группами:

```bash
/home/user1/.local/bin/cargo run --manifest-path rechprav/Cargo.toml --locked --offline -- \
  split-corpus rechprav/data/private/my-corpus-001/corpus-real-asr.jsonl \
  --seed pilot-1 --output-dir rechprav/data/private/my-split-001
```

Команда проверяет перекрытие нормализованных source/gold между группами,
назначает группы примерно в пропорции 60/20/20 и повторно валидирует все части
вместе. Выходной каталог новый; в нём `report.json`, `manifest.json` с хешем
входа и непустые `train.jsonl`, `dev.jsonl`, `test.jsonl`. На малом наборе часть
может оказаться пустой. Один запуск принимает только реальное ASR **или**
технические примеры. При одинаковом входе и seed результат воспроизводим;
до оценки на test нельзя выбирать seed по результатам корректора.

Проверка поиска: `node --test rechprav/annotator/search.test.mjs`.
Браузерный тест: `node --test rechprav/annotator/annotator.browser.test.mjs`
при наличии Chromium (`CHROMIUM_PATH` задаёт путь к нему).
