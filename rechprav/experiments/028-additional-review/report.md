# Замер обрезки истории

Временная SQLite-база с 50 000 технических записей. Команда:

```sh
node rechprav/experiments/028-additional-review/bench-history-prune.mjs
```

Скрипт сравнивает старый запрос с `OFFSET maxEntries` и новую стратегию
`COUNT(*)` плюс удаление только превышения. Он выполняет 1000 вставок в
транзакциях для каждого варианта, контролируя итоговое число строк.
Вывод сохранён в [performance.json](performance.json): Node v24.19.0,
988,81 мс против 63,94 мс, оба варианта сохранили ровно 50 000 строк.

Дополнительный одиночный замер реального `TransformationLog.add()` на
временной файловой БД с лимитом 50 000 и короткими техническими строками:

| Состояние | Прежний код | Новый код |
|---|---:|---:|
| 49 000 строк, следующие 500 добавлений | 2175 мс | 1590 мс |
| Полный лимит, следующие 2000 добавлений | 8207 мс | 6064 мс |

Второй замер включает физические транзакции и служебную сериализацию;
поэтому общий выигрыш меньше, чем у одного SQL-участка. Сравнение сделано
на одной машине в отдельных последовательных запусках. Это технический
профиль нагрузки, не данные Handy и не тест качества исправления слов.
