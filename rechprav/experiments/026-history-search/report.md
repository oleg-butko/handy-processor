# 026: поиск и фильтр истории

2026-09-26, ветка `feat/history-search-correction-filter`, baseline `6dcd3e5`.

История загружалась страницами по 10 записей, поэтому поиск по уже загруженным
карточкам пропустил бы старые записи. Добавлена фильтрация в SQLite до подсчёта
результатов и пагинации. Запрос ищет слово либо непрерывную фразу в исходном
тексте, результате или обоих полях. Регистр русских букв не учитывается;
повторяющиеся пробелы и переносы строк при поиске считаются одним пробелом.
Символы `%` и `_` трактуются буквально, без семантики SQL LIKE.

Фильтр «Только с заменой терминов и фраз» проверяет сохранённый снимок правил:
`id = recognition.terms-and-phrases`, `outcome = changed`, `changed = true`.
Изменения других правил, запуск без замены и пропущенная коррекция не подходят.
Критерий одинаков для серверного фильтра и красной метки «Замена» в карточке.
Схема БД не менялась; старые записи без снимка правил остаются доступными в
обычном поиске, но не попадают в фильтр замен.

В карточке убраны видимые подписи текстовых полей; их назначение осталось в
доступных именах. Блок «Применённые правила» свёрнут по умолчанию. Вложенное
объяснение решения показывается только для реальной коррекции с выбранным
кандидатом. Статус пропущенных/неизменивших текст правил остаётся виден после
раскрытия общего блока. При изменении поиска/фильтра страница сбрасывается на 1;
старый HTTP-ответ отменяется. Ввод поиска ожидает 300 мс после последней буквы.

веса и сохранённые записи не пересчитывались. Поиск сканирует записи истории;
специальный полнотекстовый индекс не добавлялся. При больших объёмах истории
его производительность следует оценивать на реальной рабочей БД.
