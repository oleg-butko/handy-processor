# 016 — первый прогон адаптера записи

2026-09-22. Протокол `2e5cec0`, код `3b68fd5`. Этот прогон сохранён как первая
проверенная попытка; окончательный результат — [016-editor-capture-v2](../016-editor-capture-v2/report.md).

Прошли 16 Node-тестов, в том числе SIGKILL до/после commit и конкуренция процессов.
Четыре сквозных профиля: accepted/redo-accepted 6 TP/1 FP/9 FN, undo/redo-stale
3/0/12. Это выбранные четыре правила, не весь набор из восьми правил 014/015.

После успешного прогона просмотр кода выявил недостаточную границу открытия БД:
маркировка application_id проверялась через PRAGMA уже после открытия SQLite.
Движок может восстанавливать hot journal при чтении, поэтому такая проверка
слишком поздняя для чужого файла. Изменений реальной чужой БД не было; тестовый
чужой файл в этом прогоне также остался неизменным. В `7d47d6c` добавлена проверка
сигнатуры/application_id/user_version обычным read-only чтением заголовка до SQLite.

Во втором прогоне все 16 тестов прошли снова. Данные/цены/правила/сценарии не
менялись; receipts, snapshots, events, predictions и metrics совпали.
