# 021 — отключаемое правило и объяснения в истории

2026-09-22. Ветка `feat/rechprav-rule-integration`, реализация `84e1f84`.
Новый запрос пользователя изменил очередь: вместо каталога предложений aliases
подключены проверенные методы к рабочему pipeline приложения. Автоматическое
обучение из редакторских правок не входит в эту интеграцию.

## Решение

Добавлено выключенное по умолчанию правило `recognition.terms-and-phrases`.
Aliases, формы, фразы, произношения и контекстное ранжирование зависимы:
раздельные проходы могли бы менять результаты друг друга. Они остаются одним
TermEngine с разрешением конфликтов на исходном тексте, без каскада замен.
Независимость от включения форматирующих правил проверена, но перестановка
коррекции с форматированием не разрешается: коррекция видит исходный регистр.

Rust worker загружает профиль один раз, Node вызывает его асинхронно. Есть
лимиты текста/очереди/ожидания/ответа. Ошибка, таймаут или неполный анализ
сохраняют исходник для остальных правил и записывают причину в историю.
Ресурсы и профиль не загружаются, пока метод выключен. При ручной перезагрузке
старый процесс освобождается до запуска нового; неверный профиль временно
отключает коррекцию. Публикация learned rules 018–020 здесь не подменяется
ручным TOML-профилем.

В существующем rules_snapshot сохраняются кандидаты, выбор/отказ, пороги,
контексты, исключения, веса и составляющие итогового балла. Изменение файла
профиля не меняет объяснения старой истории. Компоненты оценки проверяются
worker и Node: их сумма должна соответствовать реальному баллу кандидата.
В UI раскрываются общий результат, отдельный фрагмент и состав оценки.

## Проверка полного словаря и известного корпуса

```bash
npm run build
node rechprav/scripts/run_integration_check.mjs rechprav/artifacts/integration-repeat
```

Нужен новый выходной каталог. Используется полный подготовленный словарь
3 017 654 форм. Оценка здесь по целым строкам: gold сначала проходит прежнее
форматирование регистра/чисел/точки, затем сравнивается с полным новым pipeline.
Это проверка интеграции на известных примерах, не независимая ASR-оценка и
не сравнение span TP/FP с опытами 010/011.

| Набор | Строк | Полностью верны до коррекции | После | Испорчено исходно правильных строк |
|---|---:|---:|---:|---:|
| Девять пар пользователя | 9 | 0 | 9 | 0 |
| Controls фраз 010 | 43 | 30 | 34 | 3 |
| Controls форм 011 | 24 | 13 | 21 | 3 |

Корпуса пересекаются, результаты не суммируются. «9 из 9» объясняется в том
числе явными aliases пользовательских ошибок, не обобщением на неизвестные.
Сохраняются известные ложные исправления буквальных упоминаний:
«слово этабы содержит ошибку», «слово луколхоз смешное»,
«обсуждаем выражение нет звон», «слово свуты записано неверно»,
«обсуждаем выражение без снятия сваты». Это причина оставить метод отключаемым
и не выдавать стартовый профиль за безопасный универсальный корректор.

[Предсказания и снимки объяснений](predictions.jsonl),

## Проверки и найденные проблемы

- Полная сборка Node/UI/Rust прошла. Общий серверный прогон — 92 теста до
  добавления строгой проверки wire snapshot; после неё и нового теста отказов
  повторены затронутые наборы: 31 тест, включая 6 сценариев интеграции корректора.
- Настоящий Rust worker проверен на исправлениях, контексте/исключениях,
  конкурирующих целях, изменении веса после reload и отмене всего результата
  при исчерпании бюджета. Компоненты score проверены на реальных ответах.
- HTTP включение/выключение, защита reload от чужого origin, сохранение истории
  после повторного открытия SQLite и после изменения профиля прошли.
- Отдельные процессы имитируют зависание, переполненную очередь, падение и
  повреждённый ответ. Неверная диагностика не сохраняется как успешная коррекция;
  следующий запрос после таймаута может запустить свежий процесс.
- Браузерный тест с настоящими HTTP/SQLite/Rust прошёл: toggle, успешная правка,
  контекстный отказ, раскрытие баллов, reload, выключение, отсутствие JS ошибок.
  Проверена ширина 390 px, скриншот просмотрен. Прежние 7 браузерных проверок
  шаблонов также прошли; 2 прежних теста упаковки прошли.
- TypeScript server/UI, clippy для worker и rustfmt check прошли. Основной Rust
  алгоритм не менялся; прежние 147 Rust-тестов заново не запускались.

Первый браузерный прогон выявил прежнее поведение keepMounted-вкладки: история
не обновлялась при переходе на неё. Добавлено обновление по активной вкладке.
Затем исправлен неоднозначный test locator: у фрагмента несколько кандидатов,
поэтому выбирать надо конкретную строку. Визуальная проверка выявила ещё и
обрезание блока внутри flex group на мобильном экране. Ограничена ширина блока,
таблица получила отдельную горизонтальную прокрутку, тест теперь проверяет
границы самих элементов, а не только ширину document. Старое предположение
теста «все правила включены по умолчанию» заменено проверкой registry defaults.

Машинная запись проверок: [checks.json](checks.json). Сборка Vite выдаёт
предупреждение о размере JS chunk >700 kB; сборка успешна. Исполняемые файлы
старого launcher/SEA не перепаковывались. Проверки упаковки не означают, что
корректор уже доставлен в ранее собранный portable-каталог.

Рабочая БД, сервер и пользовательский first-plan не изменялись. Тесты используют
временные БД и отдельные localhost-порты. Нет установки зависимостей, изменения
служб или скачивания ресурсов. Следующие отдельные задачи: управляемые предложения
aliases, буквальные упоминания и подтверждённое обучение из редактора.
