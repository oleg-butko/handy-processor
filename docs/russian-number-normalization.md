# Нормализация русских числительных

## Цель

Добавить в post-processing транскрипции обратную текстовую нормализацию
(inverse text normalization, ITN): заменять русские числительные их цифровой
записью, не изменяя остальной текст.

Примеры желаемого поведения:

```text
мне нужно двадцать два файла
-> мне нужно 22 файла

не хватает двадцати двух файлов
-> не хватает 22 файлов

двацать два файла
-> 22 файла
```

Обработка падежей и исправление опечаток являются разными задачами. Падежная
форма корректна с точки зрения русского языка и должна быть приведена к
значению числа. Опечатку сначала нужно осторожно исправить, а затем передать
результат числовому парсеру.

## Исследованные готовые решения

### `to-numbers`

[`to-numbers`](https://github.com/mastermunj/to-numbers) — наиболее подходящая
готовая библиотека в экосистеме Node.js. Версия 1.1.0 написана на TypeScript,
работает на Node.js 20 и новее, не имеет runtime-зависимостей и предоставляет
отдельный импорт `to-numbers/ru-RU`.

Проверка версии 1.1.0 показала:

```text
двадцать два                 -> 22
двадцать две                 -> 22
тысяча сто                   -> 1100
миллион сто тысяч сто        -> 1100100
два целых пять десятых       -> 2.5

двадцати двух                -> 0
двухсот двадцати двух        -> 0
первого                      -> 0
двацать два                  -> 2
сто двести триста            -> 20300
```

Русский словарь библиотеки содержит главным образом начальные формы слов.
Кроме того, библиотека вычисляет одно число из всего переданного текста и
может игнорировать неизвестные слова. Поэтому её нельзя вызывать на всей
транскрипции без предварительного выделения и проверки числовых фрагментов.

Библиотеку можно использовать как быстрый прототип или как источник тестовых
примеров, но не как единственный production-парсер.

### `rus2num`

[`rus2num`](https://github.com/saarus72/rus2num) лучше соответствует русскому
ITN. Он заменяет числа внутри обычного текста, использует морфологическую
нормализацию Yargy/Natasha и обрабатывает сложные случаи вроде дробей,
`с половиной`, диапазонов и нескольких независимых чисел.

Недостаток для этого проекта — Python runtime и старые зафиксированные
зависимости: `natasha == 0.10.0` и `yargy == 0.12.0`. Это усложнит Windows SEA,
если выполнять Python во время обработки каждого запроса.

Реализацию и тестовые примеры `rus2num` полезно использовать как референс при
разработке русского TypeScript-парсера.

### NVIDIA NeMo Text Processing

[`NeMo Text Processing`](https://github.com/NVIDIA/NeMo-text-processing)
поддерживает русский ITN для чисел, дат, времени, денег, телефонов и других
классов. Это наиболее функциональный вариант, но он использует Python и
Pynini/OpenFst. Проект прямо указывает, что pip-установка Pynini на Windows не
поддерживается. Для небольшого локального SEA-сервера это слишком тяжёлый
runtime-стек.

### Морфология через `pymorphy3`

[`pymorphy3`](https://github.com/no-plagiarism/pymorphy3) — поддерживаемый
морфологический анализатор и генератор словоформ для русского языка. Его не
обязательно включать в готовый сервер. Python-скрипт может один раз получить
все формы выбранных числительных и сохранить проверенный TypeScript-файл.

Такой подход оставляет Python инструментом разработки, а готовый сервер и SEA
используют только статические данные и TypeScript.

## Выбранная архитектура

Runtime должен оставаться полностью на Node.js:

```text
Python generator (development only)
             |
             v
generated TypeScript dictionary
             |
             v
tokenizer -> number span detector -> parser -> text replacement
```

Основные свойства:

- сгенерированные данные хранятся в Git и воспроизводимы;
- Python и `pymorphy3` не нужны пользователю приложения;
- парсер заменяет только подтверждённые числовые фрагменты;
- исходные позиции, пробелы и пунктуация остального текста сохраняются;
- вычисления больших целых по возможности используют `bigint` или строки;
- неоднозначный фрагмент лучше оставить без изменения, чем преобразовать
  обычное слово в число.

## План реализации: от простого к сложному

### Этап 1. Простые количественные числа

- Создать Python-генератор статического TypeScript-словаря.
- Добавить основные формы чисел от нуля до девятисот.
- Реализовать выделение непрерывных последовательностей числительных.
- Поддержать сложение десятков и единиц: `двадцать два` -> `22`.
- Поддержать сотни: `триста сорок пять` -> `345`.
- Сохранить пунктуацию и обычные слова вокруг числа.
- Добавить unit-тесты на положительные и отрицательные примеры.

### Этап 2. Разряды и составные числа

- Добавить `тысяча`, `миллион`, `миллиард`, `триллион`.
- Реализовать умножение групп на разряд и их последующее сложение.
- Разделять независимые числа, если порядок компонентов нарушает грамматику:
  `сто двести триста` -> `100 200 300`, а не `600`.
- Перейти на безопасное представление больших целых без потери точности.

### Этап 3. Падежи и род

- Подключить `pymorphy3` только в Python-генераторе.
- Генерировать формы `одна`, `одной`, `двух`, `двумя`, `двадцати`,
  `двумястами`, `тысячах` и другие.
- Сопоставлять каждую форму с каноническим числовым компонентом.
- Проверить сгенерированный набор allowlist-фильтрами и ручными fixtures.
- Добавить количественные и порядковые формы во всех нужных падежах.

### Этап 4. Осторожное исправление небольших опечаток

- Нормализовать `ё`/`е` до fuzzy-сравнения.
- Для неизвестных потенциальных числительных использовать ограниченное
  расстояние Дамерау — Левенштейна.
- Сначала разрешить только одну вставку, удаление, замену или перестановку.
- Не исправлять короткие слова длиной до четырёх символов.
- Принимать только единственного лучшего кандидата.
- Проверять исправленный фрагмент числовой грамматикой.
- Не запускать fuzzy spell checking на всём тексте.

### Этап 5. Дроби и отрицательные числа

- `минус двадцать два` -> `-22`.
- `два целых пять десятых` -> `2.5`.
- `три с половиной` -> `3.5`.
- Определить единый десятичный разделитель для результата.

### Этап 6. Контекстные классы

Добавлять каждый класс отдельно, поскольку одинаковая последовательность слов
может интерпретироваться по-разному:

- порядковые числа и формат `22-й`;
- годы и даты;
- время;
- телефоны;
- деньги и проценты;
- диапазоны и номера документов.

### Этап 7. Проверка на реальных транскрипциях Handy

- Собрать обезличенный corpus входов и ожидаемых результатов.
- Разделить fixtures на обязательные, неоднозначные и заведомо неизменяемые.
- Измерять ложные преобразования отдельно от пропущенных преобразований.
- Для неоднозначных случаев предпочитать сохранение исходного текста.

## Критерии первой рабочей версии

Первая версия считается полезной, когда она:

- корректно заменяет единицы, десятки и сотни внутри предложения;
- не меняет текст без числительных;
- не объединяет числа через обычные слова и пунктуацию;
- сохраняет прежнее приведение к нижнему регистру и удаление конечной точки;
- генерирует runtime-словарь воспроизводимым Python-скриптом;
- успешно проходит тесты и включается в существующую SEA-сборку без Python.

## Текущее состояние

Этап 1 реализован в первом приближении:

- Python-скрипт генерирует проверяемый TypeScript-словарь;
- runtime использует только сгенерированный TypeScript;
- поддерживаются количественные числа от 0 до 999 в основных формах;
- поддерживаются родовые варианты `одна`, `одно` и `две`;
- числительные заменяются внутри обычного текста;
- несовместимые соседние компоненты разделяются на самостоятельные числа;
- добавлены unit- и интеграционные тесты.

Падежи, разряды от тысячи, fuzzy-коррекция, дроби и контекстные классы пока не
реализованы и остаются следующими этапами.
