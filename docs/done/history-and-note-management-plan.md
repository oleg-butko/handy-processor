# Управление заметками и историей: решения и выполненный план

## Цель

Добавить компактное управление сохранёнными заметками, исправить покрытие
промежуточных тем, ограничить рост SQLite-истории и дать пользователю простой
текстовый экспорт без усложнения текущей архитектуры.

## Решения

- Переименование и удаление используют существующий REST API заметок:
  `PATCH` и `DELETE /api/editor/notes/:id`.
- Undo/redo хранится в `state_snapshot` той же строки `editor_notes`, поэтому
  удаление строки автоматически удаляет и её историю. Черновик сохраняет текст,
  но перестаёт ссылаться на удалённую заметку.
- Цвета страниц задаются общими CSS-токенами поверхностей. Это позволяет новым
  карточкам и редактору одинаково поддерживать четыре темы.
- Серверный лимит хранится в расширяемой таблице `app_settings`, а не в
  браузерном `localStorage`. Он общий для launcher и обычного браузера.
- Экспорт формируется итератором SQLite и потоково записывается в HTTP-ответ.
  Первая версия намеренно остаётся человекочитаемой и экспортирует только пару
  «исходный текст — результат».

## Выполненные этапы

1. `feat(notes): rename and delete saved notes` — API, транзакционное удаление,
   компактные кнопки и подтверждающие окна.
2. `fix(ui): apply intermediate themes to all surfaces` — общие поверхности
   карточек, вложенных блоков и CodeMirror.
3. `feat(history): add configurable retention limit` — миграция SQLite,
   автоматическая очистка, API и настройка с default 50 000.
4. `feat(history): export transformations as text` — потоковый endpoint и
   экспериментальный блок скачивания.
5. Документация, полные тесты и итоговое ревью.
