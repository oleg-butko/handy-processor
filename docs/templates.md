# Шаблоны

Вкладка «Шаблоны» находится между «Список правил» и «Настройки».
Поиск и копирование работают в браузере; глобальное двойное нажатие и
вставка в другое приложение требуют Windows-лаунчер.

## Файл

Создайте `templates.txt` рядом с runtime `config.json` (в portable-сборке —
рядом с `HandyProcessor.exe`). За основу можно взять `templates.example.txt`.
Приложение не создаёт и не перезаписывает ваш файл автоматически.

Кодировка — UTF-8, допустим BOM. Одна строка — один шаблон:

```text
Работа > Ответ клиенту > Спасибо за обращение. Уточню информацию и вернусь с ответом.
Личное > Встреча > Давайте встретимся завтра в удобное для вас время.
```

Нужны ровно три непустых уровня, разделённые двумя знаками `>`.
Пробелы по краям уровней удаляются; внутренние пробелы сохраняются.
Пустые строки пропускаются. Знак `>` внутри уровня и многострочные шаблоны
пока не поддерживаются. Лимит файла — 2 МБ; 100–200 строк не требуют
специальной подготовки.

«Выбрать файл» открывает системный диалог лаунчера. Проверенный путь сохраняется
в SQLite-настройках сервера. «Файл по умолчанию» возвращает источник к
`templates.txt`, если этот файл существует и читается. «Обновить» перечитывает
источник вместе с файлом готовых слов; оба файла также читаются при переходе
на вкладку.

Ошибочные строки пропускаются с указанием номера. При ошибке чтения, UTF-8,
размере свыше лимита или отсутствии корректных строк в повреждённом файле
остаётся последняя успешно загруженная версия с предупреждением. Полностью
пустой файл считается корректным пустым списком. Сохраняйте внешние изменения
полностью перед обновлением списка: приложение не может отличить намеренно
пустой файл от промежуточного состояния стороннего редактора.

## Поиск

- По умолчанию включены уровни 1, 2 и 3, виден весь файл.
- Кнопки уровней одновременно меняют отображение и область поиска.
  Хотя бы один уровень остаётся включённым.
- Запрос — начало слова. Точка разделяет несколько обязательных префиксов:
  `сл.др` находит строки со словами, начинающимися на `сл` **и** `др`.
  Слова могут находиться в разных включённых уровнях.
- Регистр не учитывается, `ё` и `е` равнозначны для поиска. Совпавшие начала
  слов подсвечиваются; оригинальный текст сохраняется.
- Кнопки алфавита вводят буквы в позиции курсора; доступны точка, удаление
  и очистка. При вызове хоткеем запрос сохраняется и выделяется для замены.

Обе иконки справа от строки всегда используют **третий уровень**, даже
если он скрыт переключателем.

## Готовые слова

Положите `predefined-words.txt` рядом с используемым файлом шаблонов.
Если выбран файл из другого каталога, готовые слова читаются из того же
каталога. Формат — UTF-8, одно слово на строку, например:

```text
Работа
Общение
Уточнение
```

Слова отображаются кнопками между фильтром и алфавитом, в порядке файла.
Пустые строки пропускаются, пробелы по краям убираются, точные повторы
показываются один раз. Клик добавляет слово с точкой в конец запроса и сразу
обновляет результаты: `сл` + кнопка «Другие» → `сл.Другие.`.

Кнопка «Обновить» перечитывает и шаблоны, и готовые слова. Отдельного выбора
файла слов нет. Если файла нет, кнопки не показываются; ошибка чтения
показывается отдельно и не мешает пользоваться шаблонами. Лимит — 2 МБ.
Пользовательский `predefined-words.txt` в корне сохраняется при обновлении
исходников из ZIP и не добавляется в Git.

## Двойное нажатие

Справа от переключателей уровней находится строка «Хоткей» с текущей привязкой.
Нажмите её, чтобы развернуть настройки; повторное нажатие сворачивает блок.
По умолчанию блок свёрнут, заголовок и описание вкладки убраны для экономии места.

В развёрнутом блоке включите или выключите хоткей, нажмите кнопку клавиши
для записи, задайте интервал и нажмите «Сохранить». Запись требует одного
нажатия и отпускания, отменяется кнопкой, через 10 секунд или при уходе
с вкладки/потере фокуса окна или сворачивании настроек.

По умолчанию: **Win × 2, 200 мс, включено**. Интервал допускает 50–2000 мс
и измеряется между началами двух нажатий. Обе клавиши должны быть отпущены;
удержание дольше интервала, автоповтор, посторонняя клавиша и смена окна
отменяют жест. Равенство интервалу считается двойным нажатием.

Начальное значение Win принимает два левых или два правых Win. Левый,
затем правый — разные клавиши. Запись привязывает конкретную сторону.
Поддерживаются также Ctrl/Alt/Shift с указанием стороны, буквы, цифры,
F1–F24 и основные навигационные клавиши. Двойные сочетания не поддерживаются.

При включённой привязке Win **одиночное нажатие не открывает «Пуск»**.
Для Win/Alt подавляется действие меню при отпускании; сочетания с другими
клавишами проходят обычным путём. Если выбрана обычная клавиша, её одиночные
нажатия без модификаторов тоже перехватываются. Отключение привязки и выход
из лаунчера возвращают обычное поведение.

Настройки хранятся в `template-hotkey.json` рядом с runtime `config.json`.
Они применяются без перезапуска и записываются через временный файл.
При повреждении настроек перехват выключается и показывается ошибка.

## Вставка

1. Поставьте курсор в поле другого приложения.
2. Дважды нажмите выбранную клавишу: лаунчер показывает окно и выбирает вкладку.
3. Найдите строку и нажмите иконку вставки справа.

Лаунчер копирует третий уровень, скрывает своё окно, запрашивает возврат
в прежнее окно, ждёт отпускания модификаторов и проверяет цель ещё раз.
После небольшой паузы отправляет Ctrl+V через Windows `SendInput` с VK_V.
Текст остаётся в буфере; Enter, пробелы и правила обработки диктовки
не добавляются. Повторная операция блокируется до окончания первой.

Цель хранит HWND, PID и доступный HWND поля, действует до 10 минут.
Повторный хоткей в самом лаунчере сохраняет предыдущую внешнюю цель.
Обычное открытие через tray сбрасывает её; тогда доступно копирование,
а для автоматической вставки нужно вызвать вкладку из нужного поля.

Если окно закрыто, цель устарела, фокус не вернулся или буфер был изменён
до отправки Ctrl+V, автоматическая вставка отменяется. Лаунчер показывает
причину и предлагает вставить вручную. Повторной отправки Ctrl+V нет:
успешная отправка клавиш не доказывает, что приложение приняло текст.

Windows может отклонить [активацию чужого окна](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow).
[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)
ограничен уровнем привилегий целевого процесса. Конкретный HTML-input и
каретка не идентифицируются HWND, поэтому сохранение точного поля зависит
от поведения целевого приложения. Работа на защищённом рабочем столе не
поддерживается.

## Проверка

Автоматически проверены парсер, поиск, API, сохранение настроек, автомат
двойного нажатия и UI в Chromium с имитацией native-моста. Проверены типы
TypeScript и весь Rust-лаунчер для Linux и `x86_64-pc-windows-msvc`.
Это проверка компиляции Windows-кода, а не запуск Windows EXE.

Перед использованием нужно выполнить на Windows:

- Скрытое, открытое и свёрнутое окно: двойной Win показывает «Шаблоны».
- Одиночный Win не открывает «Пуск»; Win+E/D/R/L и Shift+Win+S сохраняют
  действие. Удержание, смешанные стороны и тройное нажатие не дают лишних
  активаций. После блокировки/разблокировки нет залипших клавиш.
- Изменение клавиши, интервала, отключение, отмена записи и перезапуск
  сохраняют ожидаемое поведение. Проверить одновременно с хоткеем Handy.
- Копирование/вставка в Блокнот, браузерные input/textarea, VS Code и Word
  при русской и английской раскладках, включая скрытый третий уровень.
- Закрытие исходного окна, изменение фокуса и буфера перед вставкой,
  повторный клик, приложение с повышенными правами: нет вставки в случайное
  окно или повторной отправки. При отказе доступна ручная вставка.
- Перезагрузка WebView во время вызова не теряет запрос выбора вкладки;
  переход со вкладки редактора выключает контекст диктовки редактора.

На Linux автоматические проверки запускаются из корня:

```bash
npm test
npm run typecheck
npm run test:browser
PATH="$HOME/.local/bin:$PATH" npm run test:launcher
PATH="$HOME/.local/bin:$PATH" npm run check:launcher
```

Для браузерного теста нужен Chromium: системный `/usr/bin/chromium`, путь
в `CHROMIUM_PATH` либо браузер Playwright (`npx playwright install chromium`).
Тест использует отдельный HTTP-сервер и не читает пользовательскую базу.
