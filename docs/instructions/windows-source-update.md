# Обновление исходников в Windows из ZIP

Вспомогательный Python-скрипт заменяет исходники в рабочем каталоге содержимым
самого свежего ZIP из `archive/`, не трогая уже установленные зависимости и
сборочные бинарники.

## Настройка

Откройте `unpack-sources.config.json` и задайте каталог назначения:

```json
{
  "path-dist": "C:/work/handy-processor"
}
```

Относительный путь вычисляется от каталога, в котором лежит конфиг. Например,
`"./src"` означает соседний каталог `src`.

По умолчанию в репозитории указан безопасный отдельный каталог
`./source-dist`. Перед первым рабочим запуском замените его своим Windows-путём.

## Запуск

Положите новый архив в `archive/` и выполните из PowerShell:

```powershell
py scripts\unpack_source_archive.py
```

Скрипт покажет выбранный архив, destination и backup, после чего запросит
подтверждение. Для заранее проверенного неинтерактивного запуска:

```powershell
py scripts\unpack_source_archive.py --yes
```

Другой конфиг можно передать явно:

```powershell
py scripts\unpack_source_archive.py --config C:\work\update-config.json
```

В этом случае и относительный `path-dist`, и каталог `archive/` разрешаются
относительно расположения переданного конфига.

## Что происходит

1. Из соседнего с конфигом каталога `archive/` выбирается ZIP с самым новым
   временем изменения.
2. ZIP проверяется на целостность, небезопасные пути, symlink и чрезмерный
   распакованный размер.
3. Архив полностью распаковывается во временный staging-каталог.
4. Старые исходники переносятся в соседний `<path-dist>-backup`. Если такой
   backup уже есть, создаётся новый с временной меткой; существующий backup не
   перезаписывается.
5. Новые исходники устанавливаются в `path-dist`.

Скрипт оставляет на исходных местах:

- `.git`, `.env` и runtime `config.json`;
- `templates.txt`, `predefined-words.txt` и `template-hotkey.json` в корне;
- все каталоги `node_modules`;
- SQLite-базы и журналы;
- `.venv`, `archive`, `dist`, `web-dist`, `sea-build`, `release`;
- Rust `target` и каталоги `binaries`.

Файл шаблонов с другим именем храните вне обновляемого каталога или в
сохраняемом `release/`: произвольные пользовательские имена скрипту неизвестны.

Каталоги исходных ресурсов, например `launcher/src-tauri/icons` и
`launcher/src-tauri/gen`, обновляются из ZIP.

Если установка завершается ошибкой, скрипт удаляет уже установленные новые
файлы и пытается автоматически восстановить старые исходники. Путь к backup
всегда печатается в терминале.

После успешного обновления можно выполнять обычную Windows-сборку:

```powershell
npm run build:windows:portable
```

При первом обновлении с корректором заполните кеш его Rust-зависимостей:
`cargo fetch --manifest-path rechprav/Cargo.toml --locked`. Новый ZIP содержит
исходники worker и подготовленный словарь; portable-сборка включает их runtime
в итоговый каталог. Подробнее: [коррекция терминов и фраз](../rechprav/handy-integration.md#windows-portable-и-ошибка-enoent).

Пользовательские профили коррекции редактируйте в `release/.../rechprav/`:
этот каталог сохраняется при обновлении исходников, а повторная упаковка не
заменяет уже существующие TOML. Профили в исходном `rechprav/` обновляются из ZIP
как стартовые файлы проекта.

Если изменился корневой или launcher `package-lock.json`, перед сборкой нужно
синхронизировать сохранённые зависимости:

```powershell
npm ci
npm run install:launcher
npm run build:windows:portable
```
