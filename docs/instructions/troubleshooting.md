# Решённые проблемы разработки

Краткий справочник по уже встречавшимся проблемам сборки и разработки.

## `pymorphy3` не устанавливался в Debian VM

### Симптомы

- `python3` был доступен, но команд `pip`, `pip3` и модуля `venv` не было;
- загрузка Python-пакетов пыталась подключиться к
  `127.0.0.1:7890` и завершалась `Connection refused`;
- при этом в окружении также был настроен другой рабочий HTTP-прокси.

### Причина

Одновременно существовали переменные прокси в нижнем и верхнем регистре.
Нижнерегистровые `http_proxy` и `https_proxy` указывали на неработающий
локальный прокси и имели приоритет для `curl` и `pip`.

Проблема обнаружилась сравнением переменных:

```bash
env | rg -i '^(http|https)_proxy='
```

### Решение

Для диагностической установки не менялась система: конфликтующие переменные
удалялись только из окружения конкретной команды:

```bash
env -u http_proxy -u https_proxy curl https://pypi.org/
```

`get-pip.py`, `pip` и зависимости генератора были установлены во временный
каталог под `/tmp`, после чего пакеты подключались через `PYTHONPATH`. Это
позволило выполнить реальную проверку словоформ с `pymorphy3 2.0.6`, не меняя
системный Python и не добавляя Python в runtime сервера.

Для постоянного окружения разработки предпочтительнее установить поддержку
`venv`, создать `.venv` и поставить зависимости из
`requirements-generator.txt`. Обычная генерация словаря сторонних Python-
пакетов не требует.

## Проверка сообщала, что TypeScript-словарь устарел

После добавления новых форм команда с `--check --validate-morphology`
успешно проверила морфологию, но затем сообщила, что сгенерированный файл
устарел. Это две независимые проверки: исходные данные уже изменились, а
TypeScript-файл ещё не был перегенерирован.

Правильная последовательность:

```bash
npm run generate:numerals
npm run check:numerals
npm run validate:numerals-morphology
```
