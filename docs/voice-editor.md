# Голосовой редактор

## Использование

1. Откройте вкладку **Голосовой редактор**.
2. Нажмите в текстовое поле. Индикатор должен показать
   **Контекст редактора активен**.
3. Поставьте курсор в нужное место или выделите заменяемый текст.
4. Запустите shortcut Handy для транскрипции с post-processing.

Handy получает преобразованный фрагмент от локального сервера и вставляет его
в позицию курсора обычным способом. Одна голосовая вставка поэтому является
одной операцией в истории редактора.

Кнопки **Отменить** и **Повторить** используют ту же историю, что и сочетания:

- Ctrl+Z — отменить;
- Ctrl+Y или Ctrl+Shift+Z — повторить.

Выделение рисуется собственным слоем редактора и остаётся видимым, когда
окно WebView временно теряет фокус во время голосового ввода.

Черновик автоматически сохраняется в `handy-processor.sqlite3` рядом с
executable. После перезапуска восстанавливается текст, но не undo-история.

Тему интерфейса, размер основного UI и размер рабочего текста можно изменить
на вкладке **Настройки**. Доступны системная, светлая и тёмная темы. Шрифт
редактора меняется независимо от вкладок, кнопок, карточек и заголовков. Выбор
сохраняется локально в окне приложения.

## Контекст регистра

Правило `editor.case.lowercase-inside-sentence` работает только в голосовом
редакторе:

- в начале документа и после `.`, `!`, `?` или `…` регистр распознанного
  фрагмента сохраняется;
- в середине предложения фрагмент переводится в нижний регистр;
- при неизвестном или устаревшем контексте правило безопасно пропускается.

Пробелы и закрывающие кавычки или скобки после знака конца предложения не
мешают распознаванию начала следующего предложения. При замене выделения
используется позиция начала выделения.

Настройка находится на вкладке **Список правил** в группе
**Правила голосового редактора**. Она не зависит от правила нижнего регистра
для внешней вставки.

## Активность редактора

Позиция курсора не входит в OpenAI-compatible запрос Handy. Пока поле активно,
страница передаёт серверу текст, выделение и монотонную ревизию документа:

- изменения синхронизируются с небольшой задержкой;
- heartbeat обновляет активный контекст каждые 5 секунд;
- без обновления сервер удаляет контекст через 15 секунд;
- при закрытии вкладки или уходе с неё сессия удаляется.

Состояние сессии хранится только в памяти. В историю записывается не весь
документ, а только источник трансформации и вычисленная позиция в предложении.

Текущий API Handy не сообщает приложение назначения. Поэтому сервер считает
ввод внутренним только при свежей активной сессии редактора. Поведение фокуса
overlay необходимо проверить в конкретной сборке Handy на Windows. Если
индикатор перестал показывать готовность, перед диктовкой снова нажмите в поле.

## HTTP API редактора

Черновик:

```http
GET /api/editor/draft
PUT /api/editor/draft
Content-Type: application/json

{"content":"Текст черновика"}
```

Состояние активной сессии:

```http
PUT /api/editor/sessions/:sessionId
Content-Type: application/json

{
  "documentText": "Первое предложение. ",
  "documentRevision": 12,
  "selectionStart": 20,
  "selectionEnd": 20,
  "active": true
}
```

Удаление сессии:

```http
DELETE /api/editor/sessions/:sessionId?documentRevision=12
```

Ревизия при удалении защищает от запоздавших запросов активации. Устаревшая
ревизия возвращает `409`, некорректный диапазон выделения — `400`.

## Граница первой версии

Контекст влияет на преобразование вставляемого фрагмента, но pipeline пока не
изменяет уже существующий окружающий текст. Для таких правил потребуется
отдельный канал структурированных изменений сервер → редактор с подтверждением
вставки и защитой от дублирования.
