# 016: локальный адаптер подтверждённых исправлений

Протокол до реализации, 2026-09-22. Этап разбит: 016 проверяет получение событий
и надёжность записи; объединение ручных/generated rules и live reload — следующий
этап. Корректор и UI приложения в этом опыте не меняются.

## Обследование

PlainTextEditor.updateListener передаёт только конечный snapshot/selection, без
before и признака исправления ASR. VoiceEditorPage откладывает автосохранение;
промежуточные состояния могут объединяться. PUT /api/editor/draft сохраняет
content/state/currentNoteId, backend увеличивает собственную revision. Сессия
редактора имеет ещё одну revision, служащую для актуальности контекста. Ни одна
из них не является id подтверждённого исправления. История CodeMirror хранится
непрозрачно в SQLite. Делать обучающие пары из разницы автосохранений отвергнуто:
там могут быть диктовка, стилистика, вставка и несколько несвязанных изменений.

## Проверяемый интерфейс

Standalone Node module под rechprav/editor использует доступный node:sqlite,
как backend проекта. Rust остаётся корректором/реестром. Новых зависимостей нет.
Принимается явно переданный ограниченный фрагмент, не весь документ CodeMirror.
Координаты selection относятся к before этого фрагмента в UTF-16; адаптер
конвертирует их в UTF-8 bytes и проверяет точное восстановление after.

Request: schema_version=1, request_id, fragment_id, session_id, scope,
expected_revision, kind, before, after. Для replace ещё confirmed_asr и
необязательный selection {start_utf16,end_utf16,replacement}. Для undo —
target_request_id. Передача confirmed_asr обязательна: стилистика=false.
Первое replace создаёт фрагмент при revision=0. Следующие требуют совпадения
scope, before и revision. Другой session допустим только при актуальном состоянии.
Undo поддерживает последнее неотменённое replace этого фрагмента и точную
обратную пару; redo — новое replace с новым request_id.

Журнал requests и состояние фрагмента сохраняются одной SQLite-транзакцией.
Повтор идентичного request_id возвращает прежний receipt без добавления evidence,
даже если revision уже изменилась. Другой payload с тем же id — ошибка.
Устаревший/опередивший запрос не добавляет событие; ошибочный не занимает id.
Отдельная БД с собственным application_id, не рабочая handy-processor.sqlite3.
SQLite DELETE journal + FULL synchronous. JSONL — экспорт согласованного снимка,
а не канонический накопительный файл, который нужно чинить после оборванной строки.

Лимиты прототипа: 10000 запросов, ids 1..64 ASCII, before/after/replacement
≤128 Unicode scalar values и ≤4096 UTF-8 bytes. Консервативный scalar limit
гарантирует ≤128 lexical tokens downstream; он ограничивает локальное окно,
а не длину документа редактора. Автоматического выделения окна и привязки его
к позициям большого изменяющегося документа ещё нет.

## Frozen сценарии и критерии

Сценарии фиксируются в scripts/capture_profiles.py перед реализацией:
replace→export→review→accept, повтор доставки, undo→rebuild,
redo с новым id без/с новым accept, независимый scope, unconfirmed стилистика,
emoji перед выделением, аббревиатура и split. Сравнить actual events с ожидаемыми
JSONL и четыре активных профиля на прежнем 28-строчном корпусе 014.

Отдельные проверки хранилища: изменение payload при том же id, stale/out-of-order
revision, несовпадающий before, чужой fragment/scope, invalid UTF-16 surrogate,
неверное восстановление after, неправильный undo target, неподтверждённый ввод,
повтор после рестарта, два конкурентных процесса с одной revision, SIGKILL до
commit и SIGKILL после commit до доставки receipt. В первом случае нет половины
операции, во втором повтор возвращает прежний результат без нового evidence.

Все эти сбои инъецируются только в временные экспериментальные БД. Экспорт в
новый каталог; существующий не перезаписывать. На диск сохраняются JSONL,
receipts, snapshots, хеши исходников/бинарников и результаты downstream.
SQLite runtime files остаются generated artifacts, не входят в Git.

Критерий успеха — пригодный для 014/015 детерминированный экспорт и атомарная
запись/идемпотентность при испытанных сбоях. Улучшение качества ASR, power-loss
на реальном диске, произвольный undo CodeMirror, browser outbox и живая интеграция
в этом этапе не заявляются. Отдельно документировать ограничения интерфейса.
