# Дополнительное ревью интеграции корректора

2026-09-23. Исходное состояние — `a199ba8`, ветка исправлений —
`fix/rechprav-additional-review`. Повторно проверены границы JSONL-протокола,
конкурентные запросы, переключение процессов, передача контекста и диагностики
в историю. Это проверка интеграции корректора, а не полный аудит всего проекта.

## Исправленные ошибки

1. **P2: один запрос с некорректным Unicode завершал общий worker.**
   JSON и JavaScript допускают отдельные половины суррогатной пары UTF-16,
   например `"\ud800"`. Rust `String` их не допускает: десериализация завершала
   процесс, а адаптер отклонял также остальные ожидающие запросы. Теперь такая
   строка отклоняется до отправки в worker. Коррекция пропускается только для
   неё, последующие правила остаются доступны. Исходная JS-строка сохраняется
   при пропуске; нормальные суррогатные пары, например emoji, принимаются.
   Регрессия проверена с настоящим Rust worker и конкурентным правильным
   запросом, для одиночных верхнего/нижнего суррогатов и разорванной пары.

2. **P2: сбой кандидата сразу после ready мог вытеснить рабочий профиль.**
   Если один stdout-блок содержал сначала ready, затем неверный ответ,
   обработчик уже успевал разрешить Promise загрузки, после чего сбрасывал
   состояние кандидата. Продолжение `reload()` всё равно устанавливало его
   активным и закрывало исправный прежний процесс. Теперь перед переключением
   проверяется актуальное состояние кандидата; при отказе сохраняется прежний
   профиль и возвращается ошибка. Протокольный тест воспроизводит обе строки
   одним `write`, затем проверяет сохранение прежнего PID через тестовый profile
   и успешный следующий запрос. Защита относится к сбою до переключения;
   авария уже установленного процесса обрабатывается обычным механизмом отказа.

Обе регрессии воспроизведены на прежней реализации. В первом варианте теста
Unicode отказ соседнего Promise также приводил к unhandled rejection; тест
переведён на `Promise.allSettled`, чтобы собирать оба результата. Повтор до
исправлений снова показал две ошибки, уже без необработанных Promise.
