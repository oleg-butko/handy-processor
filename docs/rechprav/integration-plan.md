# Подключение к списку правил и истории

2026-09-22, ветка `feat/rechprav-rule-integration`.

1. Один отключаемый метод для aliases, форм, фраз, произношений, контекста и
   весов. Они конкурируют за одни spans и не независимы; использовать общий
   TermEngine без каскада замен. Полный словарь служит защитой известных слов.
   Общую B2-коррекцию произвольных слов и weighted-default не подключать:
   обзор не подтвердил их надёжное преимущество.
2. Отдельный JSONL worker с однократной загрузкой ресурсов. Ограничить вход,
   очередь, время ожидания и объём диагностики. При ошибке сохранить текст,
   записать явную причину; следующий запрос может перезапустить worker.
3. Выполнять коррекцию до форматирования регистра/чисел, чтобы форматирование
   не снимало защиту uppercase и не меняло исходный контекст. Включение других
   правил не должно быть обязательным условием коррекции.
4. Сохранить решения и их баллы в существующем снимке истории. Показывать
   раскрываемые объяснения: исходный фрагмент, выбранная цель, конкуренты,
   компоненты оценки, пороги, контекст, запреты и конфликты. Баллы не проценты.
5. Проверить настоящий Rust worker, HTTP переключение, сохранение после
   перезапуска SQLite, сбой/таймаут/очередь, прежние правила и браузерный UI.
   Примеры остаются техническими; рабочая БД пользователя не используется.

Профиль — отдельный редактируемый TOML с пользовательскими весами/выключателями.
Новый метод выключен по умолчанию. Не переносить экспериментальные review tokens
в рабочие настройки и не выдавать загрузку ручного TOML за принятие learned rules.
