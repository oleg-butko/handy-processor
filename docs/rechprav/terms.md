# Экспериментальные наборы терминов

Это отдельный отключаемый проход для слов и аббревиатур, которые Handy может
распознать сильно непохоже на правильное написание. Рабочий пример:
[`terms-example.toml`](../../rechprav/configs/terms-example.toml).
В обычный B2 или сервер HandyProcessor этот проход автоматически не включается.

## Запуск

Из корня проекта, после сборки Rust и подготовки ресурсов 003–005:

```bash
rechprav/target/release/rechprav terms-inspect 'проверь пэ эн зэ' --config rechprav/configs/terms-example.toml
rechprav/target/release/rechprav terms-inspect 'проверь ввод памяти' --config rechprav/configs/terms-example.toml
rechprav/target/release/rechprav terms-review input.txt --config rechprav/configs/terms-example.toml --output-dir rechprav/artifacts/term-review-001
rechprav/target/release/rechprav terms-inspect 'проверь пэнзэ' --config rechprav/configs/terms-example.toml --disable-terms
```

`terms-inspect` показывает кандидатов, оценки, речевой вариант, расстояние,
контекст и причины отказа. `terms-review` создаёт `corrected.txt`, `debug.jsonl`
и `manifest.json` с хешами исходников/ресурсов. Диапазоны в debug относятся к
исходной строке; `file_byte_start` даёт её смещение в файле. Отдельный формат
двух строк SOURCE/CHANGES пока остаётся у обычного B2 `review`.

Нужны новые выходные файлы/каталоги. Переносы LF/CRLF/CR и байты вне замен
сохраняются. Применяются только согласованные непересекающиеся диапазоны одного
прохода; новые слова не запускают следующие замены.

`baseline_config` задаёт относительно TOML путь к конфигу, из которого берутся
словарь валидных слов, strict_yo и защитные domain/ignore. B2-исправления здесь
не выполняются. Частоты базового профиля загружаются вместе с ним для простоты
повторного использования загрузчика, но **не входят в оценку терминов**.
Отключённый проход не требует наличия базовых ресурсов.

## Управление

| Настройка | Смысл |
|---|---|
| `enabled` в корне | Общий выключатель; при отсутствии значения по умолчанию false |
| `sets[].enabled` | Включить конкретный тематический набор |
| `sets[].terms[].enabled` | Включить отдельный термин |
| `canonical` | Точный выход, включая регистр: `ПНЗ`, `слот`, `CUDA` |
| `aliases` | Явные речевые/ASR-варианты из 1–3 русских слов |
| `policy.boost` | Общая склонность к терминологическим заменам |
| `sets[].boost` | Предпочтение набора |
| `sets[].terms[].boost` | Предпочтение конкретного термина |
| `policy.min_score` | Минимальный перевес над KEEP=0 |
| `policy.min_margin` | Требуемый перевес над другой целью |
| `known_words` | `never`, `context` или `always` для диапазонов с известными словами |
| `context` | Слова-подсказки, сравнение по точному нормализованному ключу |
| `max_known_distance` | Дополнительный предел расстояния для span с известным словом; 0 запрещает буквенные правки |
| `context_patterns` | Разрешающие соседние фразы с одним `{term}` |
| `context_exclusions` | Такие же фразы, но совпадение запрещает цель |
| `require_context` | Требовать положительный контекст также для OOV; по умолчанию false |

Пример описания цели внутри набора:

```toml
[[sets.terms]]
id = "pnz"
canonical = "ПНЗ"
aliases = ["пээнзэ", "пэнзэ", "пензе", "пензэ", "бензэ", "пэ эн зэ"]
enabled = true
boost = 0.0
known_words = "context"
context = ["проверь", "модуль", "сигнал"]
```

Снижение `boost` делает выбор цели реже, повышение — чаще. Это **баллы,
не вероятность**: например, +2 не означает ни 2%, ни удвоение вероятности.
Boost не снимает запрет `known_words=never`, защиту кода/ignore/domain и не
восстанавливает обрезанный поиск. `--disable-terms` принудительно выключает
весь проход, даже если TOML включает его.

`слот` получает aliases `свод`, `ввод`; это известные русские слова. По умолчанию
known_words=never, то есть такие замены запрещены. `context` разрешает их только
при наличии подсказки; `always` разрешает и без неё, сохраняя порог score.
Слово считается известным по точному membership основного словаря. Если в диапазоне
есть хотя бы одно известное слово, применяется эта политика ко всему диапазону.

Контекстный поиск идёт в обе стороны на `context_window` lexical tokens,
исключает сам заменяемый диапазон, останавливается на пунктуации, переносе или
защищённом техническом атоме. Лемматизации нет: `плата` и `плату` — разные cues.
Это простая локальная подсказка, не понимание смысла. В опыте 006 отдельно
проверяются правильные фразы с такими же подсказками.

## Более строгие условия из опыта 007

Новые параметры необязательны: старые конфиги сохраняют прежние решения и debug.
Пример профиля с обоими наборами:
[`terms-context.toml`](../../rechprav/configs/terms-context.toml).
Это экспериментальный профиль для просмотра предложений, не выбранный автоматический режим.

```toml
# Поля внутри [[sets.terms]]; aliases и canonical задаются как раньше.
max_known_distance = 0
context = []
context_patterns = ["проверь {term}", "{term} модуля"]
context_exclusions = ["{term} на карте"]
require_context = true
```

Шаблон сопоставляется с исходным span: `{term}` занимает его целиком, включая
2–3 слова. С каждой стороны допускается до четырёх непосредственно соседних
слов, не больше context_window; хотя бы одна сторона должна быть непустой.
Например, `проверь {term} модуля` требует обе стороны одновременно. Пробелы,
табуляции и NBSP во входе эквивалентны. Регистр и е/ё нормализуются как в базовом
словаре; пунктуация/переносы, пропущенные слова и словоформы не игнорируются.
Regex, wildcard и лемматизации нет. В настройке слова разделяются одиночным пробелом.

Положительный контекст — совпадение прежнего context **или** хотя бы одного
context_pattern. Бонус даётся один раз, независимо от числа совпадений.
Исключение запрещает цель и при положительном контексте, и для OOV, и при
высоком boost. Оно также локально: `{term} данных` не совпадёт с `{term} новых данных`
или `{term}. данных`. Не следует считать это полноценным анализом предложения.

Без require_context положительные подсказки по-прежнему обязательны только
для известных слов при known_words=context. С require_context они нужны для
всех кандидатов, в том числе OOV. Это позволяет различать активные наборы по
контексту; если подходят оба, остаётся прежняя проверка перевеса/конфликта.

max_known_distance — потолок поверх общего max_distance, он не расширяет поиск.
При 0 разрешено точное совпадение **склеенных ключей**: различие сегментации
само по себе не считается буквенной ошибкой. Если хотя бы один слог оказался
известным словом, ограничение применяется ко всему span. Поэтому полезные
многословные варианты с буквенной ошибкой могут быть потеряны.

В debug добавлены context_pattern_hits, context_exclusion_hits и заданный
max_known_distance. Причины отказа включают known_distance_limit,
context_excluded и context_required. Каждая проверка шаблона учитывается
в max_comparisons вместе с aliases; обрыв отменяет все правки строки.

```bash
rechprav/target/release/rechprav terms-inspect 'проверь пензе на карте' --config rechprav/configs/terms-context.toml
rechprav/target/release/rechprav terms-inspect 'пэнзэ на стенде' --config rechprav/configs/terms-context.toml
python3 rechprav/scripts/run_context_experiment.py rechprav/experiments/my-context-run
```

## Кандидаты и решение

`mode="exact"` сопоставляет явные последовательности токенов aliases; число
пробелов/табуляций между ними несущественно. `mode="edit"` сравнивает склеенные
ключи 1–3 исходных слов со склеенным alias обычным Unicode Levenshtein.
Например, `пэ энзэ` может совпасть с `пээнзэ`. Настройка max_distance=0..2
ограничивает **расстояние до речевого варианта**, а не до букв `ПНЗ`.
Это первый проверяемый генератор; фонетическая модель ещё не реализована.

```text
score = 4 - edit_penalty * distance
          + policy.boost + set.boost + term.boost
          + context_bonus (если есть хотя бы одна подсказка)
          - known_penalty (если есть хотя бы одно известное слово)
```

KEEP имеет score=0. Нужны разрешающий gate, score≥min_score и перевес над другой
разрешённой целью ≥min_margin. Одинаковый canonical из разных aliases/наборов
получает максимум оценки, а не сумму голосов. Разные canonical считаются разными
целями; при близких баллах выполняется KEEP. Порядок наборов в файле не выбирает
победителя. Для пересекающихся диапазонов также проверяется конфликт; при
одинаковой цели и оценке по умолчанию предпочитается меньше исходных слов.

Этап 008 добавляет экспериментальный `span_tie_break` в `[policy]`:

| Значение | Порядок после score DESC |
|---|---|
| `shortest` (по умолчанию) | Число исходных токенов ASC, начало ASC |
| `distance` | Дистанция до выбранного alias ASC, число токенов ASC, начало ASC |
| `longest` | Число исходных токенов DESC, начало ASC |

Это только разрешение точного равенства score, а не новый бонус. Разница даже
меньше min_margin не считается равенством: min_margin по-прежнему относится
к конкуренции разных целей. Проверки конфликтов выполняются до выбора порядка;
неподходящие контексты и цели не становятся разрешёнными. При равной дистанции
`distance` сохраняет короткую границу. Старые конфиги не требуют нового поля.

Расстояние не доказывает границы произношения: `пэ энзэ` может целиком означать
ПНЗ, а в `обозначь символом пэ энзэ модуля` эталон сохраняет буквенное обозначение
`пэ`. Обе альтернативы могут удалить эту правильную букву. Настройка предназначена
для сравнения в review; безусловное предпочтение целого произношения не принято.
Профили для воспроизведения: `experiments/008-spans/configs/`; полная диагностика
содержит кандидатов, distance, score и исходные байтовые границы каждой правки.

```bash
python3 rechprav/scripts/run_span_experiment.py rechprav/experiments/my-span-run
```

[Протокол 008](008-spans-plan.md),
[результаты 008](../../rechprav/experiments/008-spans/report.md).

Уже правильные активные canonical, uppercase/mixed-case, код, пути, URL,
domain и ignore защищены. Речевые варианты с первой заглавной буквой допускаются;
выход всегда берётся из canonical, без автоматического изменения его регистра.
Короткие слоги разрешены специально для названий букв. Нельзя склеить через
пунктуацию или перенос; неразрывный пробел, обычный пробел и табуляция разрешены.

Поиск ограничен max_comparisons; при исчерпании бюджета вся строка остаётся
исходной с `complete=false`, даже если до обрыва нашлась хорошая цель.
Прямое сравнение со всеми aliases предназначено для небольших пользовательских
наборов. Ограничения: до 64 наборов, суммарно 4096 aliases, до 3 входных слов,
до 128 букв в сравниваемой фразе. Для больших наборов нужен отдельный опыт индекса.

## Проверка качества

```bash
rechprav/target/release/rechprav terms-benchmark rechprav/data/fixtures/terms/corpus.jsonl --config rechprav/configs/terms-example.toml --output-dir rechprav/artifacts/term-benchmark-001
python3 rechprav/scripts/run_term_experiment.py rechprav/experiments/my-term-run
```

Метрики считают точное совпадение исходного span и replacement; неверная цель
даёт FP и оставляет FN. Испорченные правильные позиции считаются по исходнику,
без zip после склейки. WER дополнительно измеряется по нормализованным токенам;
точное совпадение текста/замены сохраняет чувствительность к регистру аббревиатур.
Синтетический корпус создан вручную и не оценивает вероятность ошибки Handy.
