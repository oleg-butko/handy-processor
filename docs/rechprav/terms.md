# Экспериментальные наборы терминов

Это отдельный отключаемый проход для слов, фраз и аббревиатур, которые Handy может
распознать сильно непохоже на правильное написание. Рабочий пример:
[`terms-example.toml`](../../rechprav/configs/terms-example.toml).
В обычный B2 или сервер HandyProcessor этот проход автоматически не включается.

## Запуск

Из корня проекта, после сборки Rust и подготовки ресурсов 003–005:

```bash
rechprav/target/release/rechprav terms-inspect 'проверь пэ эн зэ' --config rechprav/configs/terms-example.toml
rechprav/target/release/rechprav terms-inspect 'проверь ввод памяти' --config rechprav/configs/terms-example.toml
rechprav/target/release/rechprav terms-review input.txt --config rechprav/configs/terms-example.toml --output-dir rechprav/artifacts/term-review-001
rechprav/target/release/rechprav terms-inspect 'проверь пэнзэ' --config rechprav/configs/terms-example.toml --disable-terms
```

`terms-inspect` показывает кандидатов, оценки, речевой вариант, расстояние,
контекст и причины отказа. `terms-review` создаёт `corrected.txt`, `debug.jsonl`
и `manifest.json` с хешами исходников/ресурсов. Диапазоны в debug относятся к
исходной строке; `file_byte_start` даёт её смещение в файле. Отдельный формат
двух строк SOURCE/CHANGES пока остаётся у обычного B2 `review`.

Нужны новые выходные файлы/каталоги. Переносы LF/CRLF/CR и байты вне замен
сохраняются. Применяются только согласованные непересекающиеся диапазоны одного
прохода; новые слова не запускают следующие замены.

`baseline_config` задаёт относительно TOML путь к конфигу, из которого берутся
словарь валидных слов, strict_yo и защитные domain/ignore. B2-исправления здесь
не выполняются. Частоты базового профиля загружаются вместе с ним для простоты
повторного использования загрузчика, но **не входят в оценку терминов**.
Отключённый проход не требует наличия базовых ресурсов.

## Управление

| Настройка | Смысл |
|---|---|
| `enabled` в корне | Общий выключатель; при отсутствии значения по умолчанию false |
| `sets[].enabled` | Включить конкретный тематический набор |
| `sets[].terms[].enabled` | Включить отдельный термин |
| `canonical` | Точный выход, включая регистр: `ПНЗ`, `слот`, `CUDA` |
| `kind` | `word` по умолчанию; `phrase` разрешает canonical из 2–3 русских слов |
| `aliases` | Явные речевые/ASR-варианты из 1–3 русских слов |
| `policy.boost` | Общая склонность к терминологическим заменам |
| `sets[].boost` | Предпочтение набора |
| `sets[].terms[].boost` | Предпочтение конкретного термина |
| `policy.min_score` | Минимальный перевес над KEEP=0 |
| `policy.min_margin` | Требуемый перевес над другой целью |
| `known_words` | `never`, `preserve`, `context` или `always` для диапазонов с известными словами |
| `context` | Слова-подсказки, сравнение по точному нормализованному ключу |
| `max_known_distance` | Предел расстояния до alias для span с известным словом; 0 требует точного речевого варианта |
| `context_patterns` | Разрешающие соседние фразы с одним `{term}` |
| `context_exclusions` | Такие же фразы, но совпадение запрещает цель |
| `require_context` | Требовать положительный контекст также для OOV; по умолчанию false |

Пример описания цели внутри набора:

```toml
[[sets.terms]]
id = "pnz"
canonical = "ПНЗ"
aliases = ["пээнзэ", "пэнзэ", "пензе", "пензэ", "бензэ", "пэ эн зэ"]
enabled = true
boost = 0.0
known_words = "context"
context = ["проверь", "модуль", "сигнал"]
```

Снижение `boost` делает выбор цели реже, повышение — чаще. Это **баллы,
не вероятность**: например, +2 не означает ни 2%, ни удвоение вероятности.
Boost не снимает запреты `known_words=never/preserve`, защиту кода/ignore/domain и не
восстанавливает обрезанный поиск. `--disable-terms` принудительно выключает
весь проход, даже если TOML включает его.

`слот` получает aliases `свод`, `ввод`; это известные русские слова. По умолчанию
known_words=never, то есть такие замены запрещены. `context` разрешает их только
при наличии подсказки; `always` разрешает и без неё, сохраняя порог score.
Слово считается известным по точному membership основного словаря. Если в диапазоне
есть хотя бы одно известное слово, применяется эта политика ко всему диапазону;
исключение — `preserve`, проверяющий фактически изменяемый участок (см. ниже).

## Фразы, словоформы и защита известных слов (010)

```toml
[[sets.terms]]
id = "punctured-wheel"
kind = "phrase"
canonical = "проколол колесо"
aliases = ["проколол колесо"]
known_words = "preserve"
max_known_distance = 1
boost = 1.0
```

В режиме edit склеенные ключи позволяют сопоставить `долгождать` с alias
`долго ждать`. Фраза `проколол колесо` позволяет исправить `проковол колесо`
по близости и сохранённому соседнему слову. Начальные/конечные слова, чьи ключи
не изменились, исключаются из фактической правки: исходные пробелы, регистр и
байты этих слов сохраняются. В debug диапазон decision — вся сопоставленная
фраза, а `candidate.replacement_edit` и итоговый `edits` показывают правку.

`known_words="preserve"` запрещает правку, если внутри её фактического диапазона
есть известное словарю слово. Поэтому `проковол` можно исправить, сохранив
известное `колесо`. У `never` даже известное слово вне фактической правки, но
внутри сопоставленной фразы, блокирует кандидата. `preserve` остаётся осторожным:
если известное слово лежит внутри единого изменяемого участка между двумя
ошибками, вся правка запрещена; внутреннего выравнивания слов пока нет.
Отказ обозначается `known_changed_word_blocked`, вес его не снимает.

Новый вид phrase требует 2–3 русских слов с одиночными пробелами, до 128 букв;
pronunciation у него запрещён. По умолчанию остаётся word с прежней проверкой
одного технического слова. Нельзя склеивать через пунктуацию, строку или код.
Чистые вставки/удаления после удаления совпадающих краёв пока пропускаются:
схема требует хотя бы одного исходного и одного выходного токена. Например,
правило `долго → долго ждать` не выполняется, а `долгождать → долго ждать` — да.
Конфликты и занятость проверяются на всей сопоставленной фразе; это может
консервативно отклонить соседнюю правку даже вне её минимального edit.

Для известного слова, которое иногда означает термин, нужна отдельная настройка:

```toml
[[sets.terms]]
id = "slot-genitive"
canonical = "слота"
aliases = ["слота", "сваты"]
known_words = "always"
max_known_distance = 0
require_context = true
context_patterns = ["без снятия {term}"]
boost = 1.0
```

Это проверяет именно `без снятия сваты → без снятия слота`, сохраняя обычное
`сваты приехали`. Нулевая дистанция сама по себе не защищает обычное слово,
если оно явно включено в aliases. Термины `слот`/`слота`, `таб`/`табы` пока
не связаны морфологией: нужные формы задаются отдельными записями и отключаются
вместе вручную или выключателем их набора. В примере выход `пнз` строчный,
как в пользовательском эталоне; старые профили с ПНЗ не меняются.

Готовые профили: [только canonical](../../rechprav/configs/terms-phrases-canonical.toml)
и [известные пользовательские ошибки с защитой](../../rechprav/configs/terms-user-phrases.toml).
Они содержат отдельные наборы `russian_phrases` и `user`. TOML перечитывается
при следующем запуске CLI; автоматического hot reload в сервере нет.
В опыте сравниваются вложенные наборы выражений 3/12/40 — это авторские
контрольные размеры, не полноценные словари русского языка.

```bash
rechprav/target/release/rechprav terms-inspect 'без снятия сваты' --config rechprav/configs/terms-user-phrases.toml
rechprav/target/release/rechprav terms-inspect 'долгождать' --config rechprav/configs/terms-phrases-canonical.toml
python3 rechprav/scripts/run_user_phrase_experiment.py rechprav/experiments/my-user-phrase-run
```

[Протокол 010](010-user-phrases-plan.md),
[результаты 010](../../rechprav/experiments/010-user-phrases/report.md).

Контекстный поиск идёт в обе стороны на `context_window` lexical tokens,
исключает сам заменяемый диапазон, останавливается на пунктуации, переносе или
защищённом техническом атоме. Лемматизации нет: `плата` и `плату` — разные cues.
Это простая локальная подсказка, не понимание смысла. В опыте 006 отдельно
проверяются правильные фразы с такими же подсказками.

## Более строгие условия из опыта 007

Новые параметры необязательны: старые конфиги сохраняют прежние решения и debug.
Пример профиля с обоими наборами:
[`terms-context.toml`](../../rechprav/configs/terms-context.toml).
Это экспериментальный профиль для просмотра предложений, не выбранный автоматический режим.

```toml
# Поля внутри [[sets.terms]]; aliases и canonical задаются как раньше.
max_known_distance = 0
context = []
context_patterns = ["проверь {term}", "{term} модуля"]
context_exclusions = ["{term} на карте"]
require_context = true
```

Шаблон сопоставляется с исходным span: `{term}` занимает его целиком, включая
2–3 слова. С каждой стороны допускается до четырёх непосредственно соседних
слов, не больше context_window; хотя бы одна сторона должна быть непустой.
Например, `проверь {term} модуля` требует обе стороны одновременно. Пробелы,
табуляции и NBSP во входе эквивалентны. Регистр и е/ё нормализуются как в базовом
словаре; пунктуация/переносы, пропущенные слова и словоформы не игнорируются.
Regex, wildcard и лемматизации нет. В настройке слова разделяются одиночным пробелом.

Положительный контекст — совпадение прежнего context **или** хотя бы одного
context_pattern. Бонус даётся один раз, независимо от числа совпадений.
Исключение запрещает цель и при положительном контексте, и для OOV, и при
высоком boost. Оно также локально: `{term} данных` не совпадёт с `{term} новых данных`
или `{term}. данных`. Не следует считать это полноценным анализом предложения.

Без require_context положительные подсказки по-прежнему обязательны только
для известных слов при known_words=context. С require_context они нужны для
всех кандидатов, в том числе OOV. Это позволяет различать активные наборы по
контексту; если подходят оба, остаётся прежняя проверка перевеса/конфликта.

max_known_distance — потолок поверх общего max_distance, он не расширяет поиск.
При 0 разрешено точное совпадение **склеенных ключей**: различие сегментации
само по себе не считается буквенной ошибкой. Если хотя бы один слог оказался
известным словом, ограничение применяется ко всему span. Поэтому полезные
многословные варианты с буквенной ошибкой могут быть потеряны.

В debug добавлены context_pattern_hits, context_exclusion_hits и заданный
max_known_distance. Причины отказа включают known_distance_limit,
context_excluded и context_required. Каждая проверка шаблона учитывается
в max_comparisons вместе с aliases; обрыв отменяет все правки строки.

```bash
rechprav/target/release/rechprav terms-inspect 'проверь пензе на карте' --config rechprav/configs/terms-context.toml
rechprav/target/release/rechprav terms-inspect 'пэнзэ на стенде' --config rechprav/configs/terms-context.toml
python3 rechprav/scripts/run_context_experiment.py rechprav/experiments/my-context-run
```

Протокол: [007-context-plan.md](007-context-plan.md).
Результаты: [отчёт 007](../../rechprav/experiments/007-context/report.md).

## Генерация произношений букв (009)

У отдельного термина можно включить `pronunciation = "ru_letters"`:

```toml
[[sets.terms]]
id = "pnz"
canonical = "ПНЗ"
aliases = ["пэнзэ", "пензе", "бензэ"]
pronunciation = "ru_letters"
known_words = "context"
max_known_distance = 0
require_context = true
context_patterns = ["проверь {term}", "{term} модуля"]
context_exclusions = ["{term} на карте"]
```

Фрагмент добавляется внутрь существующего `[[sets]]`. Полный пример:
[`terms-pronunciation.toml`](../../rechprav/configs/terms-pronunciation.toml).
Генератор добавляет `пээнзэ`, `пэ энзэ`, `пээн зэ`, `пэ эн зэ`.
Удаление поля `pronunciation` выключает генерацию и оставляет ручные aliases.
Для режима только генерации можно задать `aliases = []` или опустить aliases;
пустой список без генератора не принимается. Выключатели термина, набора и
всего прохода действуют также на сгенерированные варианты.

Первая версия принимает только 2–3 заглавные русские буквы, кроме Й/Ъ/Ь.
Латиница, цифры и более длинные аббревиатуры требуют ручных aliases.
Это явная проверяемая граница первой версии. Для Л используются `эль` и `эл`,
для остальных поддерживаемых букв — одно название из
[фиксированной таблицы](009-pronunciation-plan.md).
Перебираются все разбиения между названиями букв; до 32 вариантов на термин.
Список не обучается и не добавляет произвольные фонетические ошибки.

При включённой генерации ручные и сгенерированные aliases нормализуются
с учётом strict_yo, объединяются и сортируются; совпадения не дают повторных
голосов. Совокупный список ограничен 64 aliases на термин и 4096 на config,
включая неактивные определения. Проверка лимита до загрузки словаря использует
строгий режим ё, поэтому не рассчитывает на последующее сокращение списка.
При выключенной генерации прежний порядок и подсчёт сравнений сохранены.

В режиме exact разные разбиения — разные варианты сопоставления. В edit
пробелы удаляются перед расчётом расстояния; такие варианты сохраняются в
каталоге и расходуют бюджет сравнений, но оценка берётся по лучшему alias.
Генерация не меняет score, known-distance cap, context, shortest или защиты.

У кандидатов такого термина есть `alias_origin`: `manual`, `generated` или
`manual_and_generated`. Это происхождение конкретного выбранного alias,
а не всех возможных способов получить тот же compact key.
В manifest поле `resources.pronunciation_aliases` содержит полный активный
нормализованный каталог по наборам/терминам; у отключённого прохода каталога нет.
Без генерации дополнительные поля диагностики отсутствуют.

```bash
rechprav/target/release/rechprav terms-inspect 'контроллер пэ эль ка' --config rechprav/configs/terms-pronunciation.toml
python3 rechprav/scripts/run_pronunciation_experiment.py rechprav/experiments/my-pronunciation-run
```

[результаты](../../rechprav/experiments/009-pronunciation/report.md).

## Кандидаты и решение

`mode="exact"` сопоставляет явные последовательности токенов aliases; число
пробелов/табуляций между ними несущественно. `mode="edit"` сравнивает склеенные
ключи 1–3 исходных слов со склеенным alias обычным Unicode Levenshtein.
Например, `пэ энзэ` может совпасть с `пээнзэ`. Настройка max_distance=0..2
ограничивает **расстояние до речевого варианта**, а не до букв `ПНЗ`.
Это сопоставление строк речевых вариантов; фонетическая модель ещё не реализована.

```text
score = 4 - edit_penalty * distance
          + policy.boost + set.boost + term.boost
          + context_bonus (если есть хотя бы одна подсказка)
          - known_penalty (если есть хотя бы одно известное слово)
```

KEEP имеет score=0. Нужны разрешающий gate, score≥min_score и перевес над другой
разрешённой целью ≥min_margin. Одинаковый canonical из разных aliases/наборов
получает максимум оценки, а не сумму голосов. Разные canonical считаются разными
целями; при близких баллах выполняется KEEP. Порядок наборов в файле не выбирает
победителя. Для пересекающихся диапазонов также проверяется конфликт; при
одинаковой цели и оценке по умолчанию предпочитается меньше исходных слов.

Этап 008 добавляет экспериментальный `span_tie_break` в `[policy]`:

| Значение | Порядок после score DESC |
|---|---|
| `shortest` (по умолчанию) | Число исходных токенов ASC, начало ASC |
| `distance` | Дистанция до выбранного alias ASC, число токенов ASC, начало ASC |
| `longest` | Число исходных токенов DESC, начало ASC |

Это только разрешение точного равенства score, а не новый бонус. Разница даже
меньше min_margin не считается равенством: min_margin по-прежнему относится
к конкуренции разных целей. Проверки конфликтов выполняются до выбора порядка;
неподходящие контексты и цели не становятся разрешёнными. При равной дистанции
`distance` сохраняет короткую границу. Старые конфиги не требуют нового поля.

Расстояние не доказывает границы произношения: `пэ энзэ` может целиком означать
ПНЗ, а в `обозначь символом пэ энзэ модуля` эталон сохраняет буквенное обозначение
`пэ`. Обе альтернативы могут удалить эту правильную букву. Настройка предназначена
для сравнения в review; безусловное предпочтение целого произношения не принято.
Профили для воспроизведения: `experiments/008-spans/configs/`; полная диагностика
содержит кандидатов, distance, score и исходные байтовые границы каждой правки.

```bash
python3 rechprav/scripts/run_span_experiment.py rechprav/experiments/my-span-run
```

[Протокол 008](008-spans-plan.md),
[результаты 008](../../rechprav/experiments/008-spans/report.md).

Уже правильные активные canonical, uppercase/mixed-case, код, пути, URL,
domain и ignore защищены. Речевые варианты с первой заглавной буквой допускаются;
выход всегда берётся из canonical, без автоматического изменения его регистра.
Короткие слоги разрешены специально для названий букв. Нельзя склеить через
пунктуацию или перенос; неразрывный пробел, обычный пробел и табуляция разрешены.

Поиск ограничен max_comparisons; при исчерпании бюджета вся строка остаётся
исходной с `complete=false`, даже если до обрыва нашлась хорошая цель.
Прямое сравнение со всеми aliases предназначено для небольших пользовательских
наборов. Ограничения: до 64 наборов, суммарно 4096 aliases, до 3 входных слов,
до 128 букв в сравниваемой фразе. Для больших наборов нужен отдельный опыт индекса.

## Проверка качества

```bash
rechprav/target/release/rechprav terms-benchmark rechprav/data/fixtures/terms/corpus.jsonl --config rechprav/configs/terms-example.toml --output-dir rechprav/artifacts/term-benchmark-001
python3 rechprav/scripts/run_term_experiment.py rechprav/experiments/my-term-run
```

Метрики считают точное совпадение исходного span и replacement; неверная цель
даёт FP и оставляет FN. Испорченные правильные позиции считаются по исходнику,
без zip после склейки. WER дополнительно измеряется по нормализованным токенам;
точное совпадение текста/замены сохраняет чувствительность к регистру аббревиатур.
Синтетический корпус создан вручную и не оценивает вероятность ошибки Handy.

## Семейства явных форм (011)

[Готовая конфигурация](../../rechprav/configs/terms-families.toml) объединяет
`слот`, `слота`, `слоте`, а также `таб`, `табы`. Базовая canonical и до 16
дополнительных forms имеют общий id, boost, enabled, known_words и
max_known_distance. Это заданные пользователем формы, не автоматическое склонение.

Фрагмент внутри существующего набора TOML:

```toml
[[sets.terms]]
id = "slot"
canonical = "слот"
aliases = ["слот", "свуты"]
enabled = true
boost = 1.0
known_words = "always"
max_known_distance = 0

[[sets.terms.forms]]
canonical = "слота"
aliases = ["слота", "сваты"]
require_context = true
context_patterns = ["без снятия {term}"]

[[sets.terms.forms]]
canonical = "слоте"
aliases = ["слоте", "свате"]
require_context = true
context_patterns = ["в {term}"]
```

Вес базовой записи меняет score всех форм на одинаковую величину; итоговые
оценки могут различаться из-за контекста/дистанции/известности исходного слова.
Выключатель отключает всю семью. Для независимого веса формы нужна отдельная
запись. При отсутствующем или пустом aliases у дополнительной формы используется
её canonical. У базовой записи правила aliases остаются прежними.

У формы можно переопределить context, context_patterns, context_exclusions и
require_context. Отсутствующее поле наследуется; явное значение заменяет всё
соответствующее поле. Пустой список очищает наследованный список, false снимает
наследованный require_context. Проверка конфигурации применяется после наследования:
нельзя требовать контекст без подсказок. Общие known gates продолжают действовать.

Все активные canonical форм защищены от исправления, даже если их нет в основном
словаре. Удаление формы или выключение семьи снимает эту защиту, если её не дают
другие записи/domain/ignore; словарь продолжает влиять согласно known_words.
Поэтому удаление формы может менять и исправление ошибок, и сохранность правильного
ввода. Формы с одинаковым ключом (регистр и ё/е не различаются) внутри семьи
запрещены. Формы нельзя совмещать с kind=phrase или pronunciation в этой версии.
Глобальный лимит 4096 aliases включает все формы; отдельного бюджета семье нет.

Debug кандидата содержит family_canonical; его canonical обозначает конкретный
выход, term — общий id. Manifest resources.term_families сохраняет только активные
семьи с разрешёнными после наследования настройками всех форм, включая базовую.
active_terms считает развёрнутые записи, не число семейств. Старые конфигурации
без forms не получают новых полей диагностики.

CLI читает настройки при новом запуске; существующий экземпляр TermEngine не
перезагружается сам. Автоматическая перезагрузка сервера ещё не реализована.

```bash
rechprav/target/release/rechprav terms-inspect 'без снятия сваты' --config rechprav/configs/terms-families.toml
python3 rechprav/scripts/run_family_experiment.py rechprav/experiments/my-family-run
```

## Понижение предпочтения исходных слов (012)

`source_penalties` — независимый, необязательный список подозрительных исходных
слов/фраз. По умолчанию пуст. Каждое правило можно выключить или удалить.
[Пример конфигурации](../../rechprav/configs/terms-source-feedback.toml) использует
консервативный вес цели и контекстный штраф источнику; это исследовательский
пример, не универсальные пороги для рабочих диктовок.

```toml
[[source_penalties]]
id = "svod-weak"
enabled = true
source = "свод"
penalty = 0.5

[[source_penalties]]
id = "svod-after-removal"
enabled = true
source = "свод"
penalty = 1.0
context_patterns = ["сняли {term}"]
```

Штраф задан положительным числом: он уменьшает преимущество сохранения исходного
span. Реализация прибавляет его ко всем оценкам замены этого span относительно
KEEP, не меняя относительные оценки разных целей:

```text
score = прежняя оценка + max(совпавшие активные source penalties, 0)
```

В примере после сняли применяется 1, в другом контексте 0.5, не 1.5. Повторение
правила не усиливает вес; это не счётчик подтверждений. Допустимы конечные значения
0..10, до 128 правил, до 32 context_patterns у правила. Пустой список шаблонов
означает глобальное действие; непустой — достаточно любого совпадения. Для
контекста действуют прежние границы, нормализация и бюджет поиска.

Source — 1–3 русских слова через одиночные пробелы в настройке. Сравнение точное
по нормализованным ключам целого рассматриваемого span, независимо от числа
горизонтальных пробелов/табуляций во входе. Не используется нечёткое сопоставление
source или поиск подстроки. Для phrase это весь совпавший диапазон, до сокращения
неизменных краёв edit. Штраф может задаваться и неизвестной словарю строке, но
её подозрительность не доказывает, какой термин имелся в виду.

Штраф не создаёт aliases, не увеличивает дистанцию и не обходит known_words,
max_known_distance, require_context, исключения, защиту canonical/кода/URL.
Нет подходящей цели — нет исправления. Равные цели остаются конфликтом даже
при большом штрафе; для выбора нужна информация о цели/паре/её контексте.
Debug содержит source_penalty и source_penalty_hits (id всех совпавших правил,
в том числе более слабых); нулевое значение и пустые hits опускаются.
Manifest effective_config хранит полные правила, включая отключённые.

Правила относятся ко всему данному профилю, не принадлежат отдельному набору
терминов. Выключение набора убирает его цели, но не выключает source_penalties
для других активных наборов. В профилях разных доменов списки следует задавать
отдельно; будущий редактор должен явно сохранять область применения предложения.
Общее enabled=false отключает весь проход. При исчерпании бюджета никакие
частичные исправления не применяются. Старые настройки без поля сохраняют
прежнюю диагностику и число сравнений.

```bash
rechprav/target/release/rechprav terms-inspect 'сняли свод' --config rechprav/configs/terms-source-feedback.toml
python3 rechprav/scripts/run_feedback_experiment.py rechprav/experiments/my-feedback-run
```

[Протокол и будущий процесс редактора](012-feedback-plan.md),
[результаты опыта](../../rechprav/experiments/012-feedback/report.md).
Вероятности, обучение по истории и автоматическая запись в словарь пока не реализованы.


## Взвешенная буквенная дистанция (013)

Опциональная секция policy.weighted_distance заменяет обычный порог edit-поиска
порогом стоимости. Доступна только при mode="edit". Без неё всё работает как
раньше. [Пример](../../rechprav/configs/terms-weighted.toml) — фиксированная гипотеза
для опытов, не обученная модель и не рекомендуемый всем профиль.

```toml
[policy.weighted_distance]
max_cost = 100
insertion = 100
deletion = 100

[[policy.weighted_distance.substitutions]]
from = "п"
to = "б"
cost = 50
```

Обычная операция стоит 100, равные буквы — 0. Здесь п→б стоит 50; обратную
замену нужно указать отдельно. insertion добавляет букву к распознанному источнику,
deletion удаляет из источника лишнюю букву.
Направление сравнения всегда источник → alias. Неперечисленные замены стоят 100.
Для модели без замен явно указать substitutions=[] в основной секции.

Стоимость задана целыми числами: insertion/deletion и substitutions 50..200,
max_cost 0..200, до 64 уникальных направленных замен. Буквы настройки — одиночные
строчные а..я без ё; нормализация ё/е остаётся прежней, отдельного правила ё нет.
Одинаковые from/to, повторы направления и неверные границы отклоняются.
Нулевой порог допускает только совпадение склеенных ключей; это не spaced exact.

При включении модели max_distance не управляет отбором и score: используется
max_cost. Score вычитает edit_penalty * weighted_cost, где weighted_cost —
целая стоимость /100. В debug distance остаётся обычным Levenshtein,
weighted_cost содержит отдельную стоимость. max_known_distance и span_tie_break
"distance" продолжают использовать обычную дистанцию. Поэтому дешёвая замена
не позволяет обойти cap для существующего слова. Среди aliases сначала
предпочитается проходящий raw cap, затем меньшая стоимость, raw distance и
лексикографический alias. Если ни один не проходит, кандидат сохраняется с
запрещающим gate для диагностики. Остальные защиты/контексты/конфликты не меняются.

Модель сравнивает буквы, а не фонемы; нет многобуквенных операций, перестановка
по-прежнему требует нескольких правок. Порог 200 и минимальная цена 50 ограничивают
допущенный путь четырьмя операциями. Входы ограничены 128 буквами; каждый alias
считается одним comparison, но вычисление weighted DP дороже обычной проверки.
Отдельного ограничения количества DP-ячеек нет. Для большого словаря нужен
отдельный опыт индекса и бюджета вычислений; нынешний проход линейный.

```bash
rechprav/target/release/rechprav terms-inspect 'клиппорт' --config rechprav/configs/terms-weighted.toml
python3 rechprav/scripts/run_weighted_experiment.py rechprav/experiments/my-weighted-run
```

[Протокол](013-weighted-plan.md), [результаты и timings](../../rechprav/experiments/013-weighted/report.md).


## Предложения из подтверждённых исправлений (014)

[Отдельный инструмент feedback_draft](feedback-drafts.md) читает журнал correction/
retract и экспортирует выключенный exact-профиль: пары, обязательный соседний
контекст, фиксированный вес, scope и evidence ids. Это не глобальное изменение
aliases/весов существующего термина. Без контекста применяется known_words=never.
Подтверждение ASR-ошибки не включает правило автоматически; опыт явно моделирует
принятие в отдельных копиях конфигурации. [Результаты](../../rechprav/experiments/014-feedback-drafts-v2/report.md).
