# 013 — взвешенная буквенная дистанция

Протокол до кода/измерений, 2026-09-21. После 012 отдельная проверка новых
искажений, не внесённых в aliases. Веса/контексты/формы/known gates неизменны
между профилями; source penalties отключены во всех новых профилях.

Политика получает optional weighted_distance только для mode=edit. Стоимости
целочисленные: обычная операция 100; insertion/deletion 50..200; до 64 явных
направленных замен одиночных русских букв а..я (без ё), стоимость 50..200.
Равные буквы стоят 0, остальные замены 100; max_cost=0..200 задаёт порог.
Направление: распознанный источник → alias. Работа с ё остаётся у нормализации.
При включённой модели max_cost заменяет max_distance для генерации/score;
max_known_distance и tie-break distance используют обычный Levenshtein.
При выборе alias предпочитать проходящий raw known cap, затем меньшую weighted
стоимость, raw distance и лексикографический alias. Без модели поведение прежнее.

Сравнить edit-1, edit-2, weighted-uniform (100, порог100), weighted-pairs
(порог100, обе стороны б/п в/ф г/к д/т ж/ш з/с по50), weighted-vowels
(также а/о е/и по50), weighted-wide (те же пары+гласные, порог150), weighted-gaps
(пары+гласные, вставка/удаление75, порог100). Это авторские гипотезы, не таблица
частот ошибок русского ASR. Профили и корпус замораживаются до реализации.

Термины: клипборд, локалхост, слот со слота/слоте, таб с табы, недозвон,
пнз с единственным произносительным alias пээнзэ. Известные ошибки из девяти
пользовательских пар не добавлять. Все термины boost=1, always, cap=0;
у слота/слоте сохраняются контексты 011. В обычных фразах preserve не меняется.
Новый synthetic/dev корпус отдельно от девяти user-reported/dev примеров.
Разделить прямые aliases, новые OOV ошибки, реальные слова, буквальное обсуждение,
положительные склейки/разделения, защиту код/URL/регистр и дальние ошибки.

Проверки: uniform эквивалентен edit-1 по текстам/edits/числу сравнений; полный
DP с независимым oracle на коротких строках; направленность и границы порога;
raw cap/конфликты/бюджет/защиты; все 155 прежних прогонов побайтно. Новые метрики
считать независимо. После замера не добавлять исключения и не подбирать веса.

Измерить warm analyze отдельно от загрузки/JSON и подсчитать comparisons и
кандидатов до gates. 3 последовательных прогона edit-1/edit-2/weighted-vowels/
weighted-gaps с циклической перестановкой порядка, 30 повторов корпуса после
разогрева. Без параллельного replay во время timing. Сохранить p50/p95/p99,
сырой ряд, hashes/config/binary, load time; не считать это production latency.
DP ограничен длиной128, max_cost200 и положительными ценами, не меняет hard
budget comparisons. Поиск линейный по aliases, отдельного DP cell budget нет.

Принять только опциональный механизм, если корректен. Default/оптимальную модель
не выбирать по авторскому набору; tradeoff TP/FP и вред описать независимо.
