# 010 — пользовательские примеры, фразы и управляемость

2026-09-21. Новые примеры пользователя меняют приоритет: взвешенная дистанция
отложена до поддержки нескольких выходных слов и проверки словарных настроек.
Протокол фиксируется до реализации и измерений. Контроль: 0d258ef/2bde59a.

Сохранить все девять исходных пар дословно, отдельно от синтетики. Восемь
однозначных пар — user-reported real_asr/dev (без аудио и сведений о модели),
Пара `без снятия сваты → долго ждать` первоначально сохранена как ambiguous.
До реализации пользователь уточнил её: `без снятия сваты → без снятия слота`.
Первоначальная запись остаётся в raw, уточнение — в clarifications.json;
теперь все девять пар участвуют в оценке. Не исправлять примеры по догадке.
Регистр `пнз` в пользовательском gold сохраняется.

Добавить `kind="phrase"` с canonical из 2–3 русских слов. По умолчанию
kind=word, прежняя проверка одного технического слова сохраняется.
Фразы используют прежние aliases/score/гейты/бюджеты/переключатели наборов.
Не вводить одновременно фонетическую дистанцию, морфологию или каскад B2.
Совпадающие начальные/конечные слова фразы сохранять в исходных байтах:
`проковол  колесо → проколол  колесо` меняет только `проковол`.
Это нужно и для честного сравнения с B2 по минимальным gold spans.
Чистые вставки/удаления без заменяемого исходного/выходного токена пока
не поддерживаются. Конфликты по-прежнему проверяются на полном диапазоне фразы.

Слои данных: полный прежний русский словарь; отдельный набор обычных выражений;
отдельный пользовательский набор терминов и фраз с ними. Обычные выражения
заморозить в трёх вложенных авторских наборах 3/12/40. Это только размеры
контрольного опыта, не маленький/средний/большой словарь русского языка вообще.
Для настоящих крупных ресурсов впоследствии отдельно проверить источник,
лицензию, покрытие, качество, время загрузки/поиска и расход памяти.

Пользовательские canonical: клипборд, табы, локалхост, недозвон, слот, слота, пнз,
фраза `недозвон до`. Формы `табы` и `слота` заданы явно: генерации словоформ
ещё нет. `slot-term-off` выключает обе записи слот/слота. Добавлены синтетические
контроли правильного `слота` и обычного известного слова `сваты`.
Первый вариант использует только canonical в aliases; отдельный вариант
добавляет распознанные ошибки пользователя. Последний является подгонкой
под известные пары, а не доказательством обобщения.

Профили: disabled; phrases-only; canonical-small/medium/large;
canonical-large-distance2; learned-large; learned-low/high (boost всех
пользовательских терминов −2/+2); user-set-off; slot-term-off;
conflict и prefer-user (конкурирующий термин для `свуты` и `пнзэ`, затем
boost пользовательского набора +1). Базовая policy из 009: edit-1, shortest,
score/margins прежние. Обычные фразы: boost=1, known_words=always,
max_known_distance=1. Пользовательские элементы: boost=1,
known_words=always, max_known_distance=0. Так веса не обходят запрет
нечёткой замены известного слова. Контекст не обязателен: сами пользовательские
примеры часто даны без него; риск на обычных фразах измеряется явно.
После уточнения `сваты → слота`, до измерения, добавлен профиль learned-context:
та же learned-large настройка, но для слота в родительном падеже обязателен
соседний шаблон `без снятия {term}`. Сравнить его с обычным употреблением
`сваты приехали к невесте`, не распространять этот вывод на все контексты.
Также до измерения добавлен отдельный learned-safe: поверх learned-context
обычные выражения получают known_words=preserve. Запрещена замена известного
слова внутри фактического edit, но допускается известное слово в сохранённых
краях фразы. Этот вариант сравнивается с learned-context отдельно, без изменения
весов. Если внутри единого оставшегося edit есть известное слово, правило
консервативно запрещает всю правку; внутреннее выравнивание пока не реализовано.

правильным позициям, точные строки, WER и число сравнений. Результаты по
размерам наборов и весам не объединять в одну оценку.
