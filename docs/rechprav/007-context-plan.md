# 007 — защита известных слов и привязанные контекстные фразы

Протокол до реализации и замеров. Основание — ошибки 006: `пение → ПНЗ`,
город Пенза, ввод данных, свод правил и неразличение ПНЗ/БНЗ. Пороги score,
веса и aliases остаются прежними; общий max_distance=1.

1. Добавить optional `max_known_distance` у термина: 0 запрещает буквенные
   изменения в известных словах, но сохраняет совпадение склеенных ключей.
   Если хотя бы один токен span известен, ограничение действует на весь span.
   Проверить потерю полезных known-word и multiword исправлений.
2. Добавить точные шаблоны `context_patterns` с одним `{term}` и 0–4 словами
   непосредственно перед/после исходного span. Они дают положительный контекст
   наравне с прежними одиночными cues; в опыте старые cues заменяются шаблонами.
   Нельзя переходить пунктуацию, перенос или технический атом. Без лемматизации.
3. Добавить `context_exclusions` того же вида: совпадение запрещает цель,
   в том числе для OOV, независимо от boost. `require_context=true` требует
   положительного контекста также для OOV; по умолчанию false для совместимости.
4. Развести контексты hardware/lab, активировать оба и проверить маршрутизацию
   без изменения приоритетов. Оба подходящих контекста должны сохранять конфликт.
5. Старые конфиги без новых полей должны воспроизвести 006 побайтно.

Матрица на двух отдельных корпусах (006 и новом 007): legacy, known-exact,
phrases, known-exact+phrases, +exclusions, +require-context, legacy-conflict,
routed-both, routed-both-without-exclusions. Все изменения — отдельные ablations;
последние сравнения показывают композицию. Приоритеты не подгоняются.

Фразы фиксируются в `data/fixtures/term-context/policy.json` до реализации.
Они придуманы по наблюдениям 006, поэтому улучшение на 006 — результат разработки,
не независимая оценка. Новый корпус также вручную создан для проверки механики,
содержит полезные/ложные совпадения шаблонов, пропущенные словоформы, противоречивый
контекст, границы и потери OOV без подсказки. Это не реальный ASR и не blind test.

Сравнивать TP/FP/FN по исходным spans, повреждённые правильные позиции,
точные строки/WER, причины отказов и все изменения относительно legacy.
Не смешивать два корпуса в одну оценку и не менять их после просмотра результатов.
Шаблоны входят в бюджет max_comparisons; при обрыве сохраняется вся строка.
Выбрать проверенные компоненты для дальнейшего review, не объявлять автоматический
профиль пригодным только по синтетике. Фонетика и интеграция с B2 остаются вне 007.
