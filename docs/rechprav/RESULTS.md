# Результаты Rechprav

Обновлено: 2026-09-20. Работают подготовка корпуса, просмотр, KEEP, B1 и B2
с частотами и сравнением с исходником. Проверен независимый полный словарь,
добавлены компактный индекс и готовая частотная таблица с сохранением результатов. Победитель для реального ASR не выбран; по выбору
пользователя пока используются технические примеры. Проверены отдельные отключаемые
наборы терминов с аббревиатурами, конфликтами и заменами нескольких исходных слов.

| Проверка | Результат |
|---|---|
| Текущий pipeline | TypeScript, синхронный реестр правил |
| Существующая близкая функция | Ограниченная коррекция русских числительных |
| История | ASR-вход и результат правил; ручного gold это не даёт |
| Размеченные данные | Пользователь подтвердил: пары пока не подготовлены; разметка входит в первый этап |
| Rust/Cargo | Найдены в `~/.local/bin`; Rust/Cargo 1.98.0, установка не понадобилась |
| Первичные источники | Проверены пакеты OpenCorpora/wordfreq и условия русского Hunspell; сайт OpenCorpora недоступен инструменту просмотра |
| Технические данные | 67 tokenizer fixtures, исходные корпуса 12/27 записей, терминологический набор 43 записи |
| Проверки | 67 тестов, clippy без предупреждений, rustfmt, offline release build |
| Качество и производительность коррекции | B1/B2 на синтетике; сравнение BTreeMap/packed trie с проверкой кандидатов и startup/RSS/lookup; реальный ASR, FST и SymSpell ещё не оценены |

Первичный [отчёт](../../rechprav/experiments/000-inventory/report.md) и
[снимок среды](../../rechprav/experiments/000-inventory/environment.json).

## 001 — KEEP и инфраструктура

[Отчёт и воспроизведение](../../rechprav/experiments/001-foundation/report.md),
[метрики](../../rechprav/experiments/001-foundation/keep/metrics.json),
[пример review](../../rechprav/experiments/001-foundation/review/review.txt).

| Показатель на искусственном корпусе | KEEP |
|---|---:|
| Записи / source tokens / gold tokens | 12 / 37 / 37 |
| Ошибки 1→1 / неподдерживаемые compound spans | 6 / 2 |
| TP / FP / FN для 1→1 | 0 / 0 / 6 |
| Правильные входные позиции / испорченные | 28 / 0 |
| Precision | N/A: нет предложенных замен |
| Recall / F0.5 / FCR | 0 / 0 / 0 |
| WER до / после | 10/37 / 10/37 (27.03% / 27.03%) |

Это ожидаемые контрольные числа, не доказательство качества. Скорость алгоритмов,
RAM, recall@K и доверительные интервалы на реальных данных ещё не измерялись.
Сохранённое время evaluation включает валидацию/токенизацию/расчёт метрик;
его нельзя использовать как latency корректора.

Будущая сводка должна содержать описание corpus/split и словаря, commit/config,
TP/FP/FN/H/C, precision/recall/F0.5/F1/FCR с интервалами, WER до/после,
candidate recall@K, latency p50/p95/p99, throughput, RAM, размер и сборку индекса.
Для каждого лидера — разбор ошибок, ограничения и ablation. Формулы и порядок
выбора определены в [протоколе](experiment-protocol.md).

Не заполнять будущие сравнения ожидаемыми числами. Пока нет реальных измерений,
все выводы о превосходстве SymSpell, FST, фонетики и контекста — гипотезы.

## 002 — B1 и роль защит

[Отчёт, все девять ошибок и воспроизведение](../../rechprav/experiments/002-baseline/report.md),
[машинная таблица](../../rechprav/experiments/002-baseline/comparison.csv),
[пример исправлений](../../rechprav/experiments/002-baseline/review/review.txt).

Новый синтетический корпус: 27 записей, 62 gold tokens, 44 правильные исходные
позиции, 15 ошибок 1→1 и 2 compound spans. Словарь — 57 заданных словоформ;
это стресс-проверка, не репрезентативная выборка речи. WER до: 19/62 = 30.65%.

| Вариант | Верных / неверных правок | Precision | Испорчено правильных слов | WER после |
|---|---:|---:|---:|---:|
| KEEP | 0 / 0 | N/A | 0 | 30.65% |
| B1 со всеми защитами | 9 / 2 | 81.82% | 1 | 17.74% |
| Без domain | 9 / 3 | 75.00% | 2 | 19.35% |
| Без ignore | 9 / 3 | 75.00% | 2 | 19.35% |
| Разрешён titlecase | 10 / 3 | 76.92% | 2 | 17.74% |

Вывод: B1 полезен как исходная точка сравнения, но недостаточен для автоматической
коррекции. Единственность кандидата не защищает от пробелов в словаре.
Domain/ignore и защита заглавных слов сохранены. Следующие проверки — полноценный
словарь и частоты, затем уточнение решения «заменить / оставить». Числа выше
не переносить на настоящую историю Handy.

## 003 — полный словарь и частоты

[Отчёт с разбором ошибок](../../rechprav/experiments/003-frequency/report.md),
[таблица](../../rechprav/experiments/003-frequency/comparison.csv),
[ресурсы и лицензии](resource-sources.md). Корпус тот же, параметры до опыта
зафиксированы в commit `f289652`; подгонки после просмотра результатов не было.

| Вариант | Верных / неверных правок | Испорчено правильных слов | WER после |
|---|---:|---:|---:|
| B1, 57 форм | 9 / 2 | 1 | 17.74% |
| B2, 57 форм + частоты | 6 / 1 | 0 | 20.97% |
| B1, полный словарь | 4 / 0 | 0 | 24.19% |
| B2, полный словарь + частоты | 5 / 0 | 0 | 22.58% |
| B2, вес частоты 0 | 0 / 0 | 0 | 30.65% |

Полный словарь убрал неверные правки `капер → катер` и `савет → завет`, но добавил
неоднозначности. B2 вернул `ошипку → ошибку`; популярность сама по себе не решает
`маско`, а `драйве` оказалось известной формой. Технического `дебаггер` в полном
ресурсе нет. Ни один метод не признан достаточно проверенным для автоисправления.
Пять верных предложений — четыре повторения одной пары и ещё одна пара;
precision=100% и FCR=0 здесь не являются оценками качества на настоящей речи.

Полный B2: 3 017 654 нормализованных словоформ, 661 389 частотных ключей;
загрузка 15.70 s, peak RSS 1593.6 MiB. Warm analyze p95=1.110 ms на короткую
синтетическую запись, 2700 измерений внутри одного процесса. Кеш ОС не очищался.
Следующий этап — компактный индекс при неизменных кандидатах и scorer, отдельные
замеры lookup и нескольких запусков. B2 full сохранён как контрольная точка,
интеграция в Handy отложена.

## 004 — компактный trie

[Отчёт](../../rechprav/experiments/004-packed-trie/report.md),
[измерения](../../rechprav/experiments/004-packed-trie/summary.json),
[описание формата](packed-index.md). Реализация `91b1d4b`.
Файл `.rpt` строится заранее; узлы и написания хранятся в общих массивах.

| Показатель, три процесса на вариант | BTreeMap + B2 | Packed + B2 |
|---|---:|---:|
| Медиана загрузки | 15.306 s | 3.551 s |
| Медиана resident RSS | 1505.19 MiB | 191.28 MiB |
| Наибольший peak RSS | 1592.44 MiB | 210.39 MiB |
| Медиана per-run p95 полного distance=1 lookup | 1.886 ms | 1.799 ms |
| Метрики прежнего корпуса | 5 TP / 0 FP / 10 FN | Точно те же |

224 запроса, включая длины до 128, distance=2 и ограничения поиска: одинаковы
все кандидаты, scores, порядок, полнота и visited_nodes. Вывод B2 побайтно повторил
003. Packed принят для следующих опытов за сокращение RSS в 7.87 раза и загрузки
в 4.31 раза. Устойчивое ускорение самого поиска пока не доказано.

Ориентир ≤256 MiB выполнен, startup ≤1 s — нет. Даже без частот packed грузится
около 2.03 s; одной упаковки TSV недостаточно. Следующий этап — раздельное
измерение фаз загрузки и точечное устранение подтверждённых затрат. Проверки
целостности сохраняются. Затем — технические цели и более сложные исправления.

## 005 — разбор загрузки и готовые частоты

[Отчёт и отклонённые варианты](../../rechprav/experiments/005-loading/report.md),
[измерения](../../rechprav/experiments/005-loading/packed-frequency/summary.json),
[формат `.rpf`](packed-frequency.md). Принятая реализация `dde352b`.

Раздельные замеры показали две крупные статьи затрат: два SHA256-прохода по
словарю и построение частотного BTreeMap из TSV. Обновление sha2 0.10.9→0.11.0
не дало убедительного выигрыша на этой VM; зависимость возвращена к 0.10.9.
Для частот реализована готовая таблица с бинарным поиском и точными `f64`.

| Три процесса на вариант, один бинарник | Packed trie + TSV | Packed trie + `.rpf` |
|---|---:|---:|
| Медиана загрузки | 3.567 s | 2.338 s |
| Медиана разбора/проверки частот | 1326.33 ms | 163.39 ms |
| Медиана resident RSS | 189.75 MiB | 146.21 MiB |
| Наибольший peak RSS | 210.35 MiB | 146.23 MiB |
| Медиана per-run warm analyze p95 | 0.630 ms | 0.679 ms |
| Метрики прежнего корпуса | 5 TP / 0 FP / 10 FN | Точно те же |

Все 661 389 значений частоты побитно проверены при сборке; предсказания и метрики
побайтно повторили 003. Принят `.rpf` для следующих опытов за меньшие загрузку и
RSS. Файл частот немного вырос: 20.93→21.49 MiB. Warm analyze не ускорился;
небольшой возможный штраф нового поиска требует отдельного измерения при
необходимости. Ориентир startup≤1 s не достигнут, проверки не отключались.

Следующий этап 006 — отдельный технический словарь кандидатов с проверкой ложных
замен и неоднозначности при прежнем scorer. Дальнейшую оптимизацию startup
отложить; перед интеграцией измерить один постоянно работающий процесс.

## 006 — управляемые наборы терминов

[Отчёт](../../rechprav/experiments/006-terms/report.md),
[12 профилей](../../rechprav/experiments/006-terms/comparison.csv),
[инструкция и настройки](terms.md). Код `b4e9c31`, ветка `feat/rechprav-term-profiles`.
По уточнению пользователя включены `свод/ввод → слот`, произношения ПНЗ,
ошибки из 2–3 слов и конфликтующие тематические наборы.

43 синтетические записи, 23 gold spans (8 multiword), 94 правильные исходные
позиции. Score и три уровня boost — предпочтения, не вероятности. Новые CLI
`terms-*` отделены от B2; измеряются точные spans и вред правильным позициям.

| Вариант | TP / FP / FN | Испорчено правильных позиций | WER |
|---|---:|---:|---:|
| Выключен | 0 / 0 / 23 | 0 | 30.77% |
| Явные aliases + context gate | 13 / 5 / 10 | 3 | 14.53% |
| Edit-1 к речевым вариантам + context gate | 18 / 6 / 5 | 4 | 7.69% |
| Edit-2 | 19 / 9 / 4 | 8 | 10.26% |
| Edit-1, только OOV | 10 / 2 / 13 | 0 | 19.66% |
| Известные слова без context gate | 20 / 10 / 3 | 8 | 9.40% |

Edit-1 исправил 5/6 новых вариантов произношения и все 8 multiword spans.
При равных конфликтующих наборах выполняется KEEP; веса и включение наборов
управляют выбором. Boost ПНЗ −2 дал 16 TP/4 FP, +2 не изменил 18/6.

Недостаток: контекстные слова «проверь», «модуль», «плата» разрешили неверные
замены города Пензы, настоящего ввода данных и свода правил. Нечёткий поиск
добавил `пение → ПНЗ`. Distance=2 дал +1 TP, но +3 FP: не принят для этого профиля.
Выбор неправильного набора создаёт неверную цель даже на настоящей ошибке.

Приняты настройки, aliases, точные диапазоны и отказ при конфликте; автоматический
профиль не выбран. B2 на старом корпусе побайтно повторил 003. Следующий этап 007:
отдельная политика нечёткого поиска по известным словам, более точные контекстные
условия и новые контрпримеры до изменения правил. Фонетика и композиция с B2 —
отдельные последующие проверки.
