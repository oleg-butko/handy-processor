# Ревью интеграции корректора

2026-09-23. Проверена реализация `84e1f84` и её документация `2c28a9b`:
управление worker, границы протокола, HTTP/остановка сервера, сохранение
объяснений и UI. Исправления — `b9dbe0e`, ветка `fix/rechprav-review-lifecycle`.

| Приоритет | Ошибка | Исправление и проверка |
|---|---|---|
| P1 | При синхронной ошибке spawn, например пустом пути executable, общий startup promise оставался pending. Первый запрос получал ошибку, последующие зависали без таймера | Ошибка отклоняет общий promise и очищает состояние. Два последовательных запроса с неверным путём завершаются отказом |
| P2 | Перезагрузка сначала уничтожала работающий процесс. Опечатка в TOML отключала коррекцию до исправления файла | Кандидат загружается отдельно; переключение происходит после ready. При ошибке/таймауте продолжает работать прежний профиль |
| P2 | Одинаковый предел 32768 символов применялся к результату и полям диагностики. Допустимый короткий вход с повторяющимся alias мог дать более длинный правильный результат, который отвергался целиком | Отдельный предел результата. Настоящий Rust worker проверен на 600 заменах короткого alias длинным термином, с усечённой диагностикой |
| P2 | При закрытии сервер сначала ждал HTTP-запросы, в том числе зависшие на загрузке worker. После ранней отмены worker оставались ставшие неактивными keep-alive соединения | Worker закрывается до ожидания HTTP; неактивные соединения повторно закрываются после завершения ответов. Проверен managed server с зависшим дочерним процессом: ответ сохраняется, БД закрывается после записи |
| P2 | Запоздалый GET статуса мог перезаписать состояние после успешного reload; сообщения об ошибках могли оставаться после успешной загрузки | Номер актуального запроса, игнорирование старых ответов, очистка ошибки, обновление при раскрытии карточки. Браузерный тест задерживает старый GET до завершения reload |

Четыре серверных регрессии воспроизведены до исправления: для первых трёх
новые тесты завершились ошибками; тест остановки также показал незавершённый
процесс. Для UI проверены порядок асинхронных обновлений и новый тест с
намеренно задержанным ответом. Тест checkbox теперь ожидает обновление после
HTTP-сохранения, а не требует немедленного переключения controlled input.

Перезагрузка проверена также при конкурентных запросах: старый запрос сохраняет
идентификатор своего профиля после переключения, новые используют новый.
Одновременно может быть один кандидат либо одно поколение, завершающее запросы,
помимо активного. Общая очередь ограничена прежними восемью запросами.
Повторная перезагрузка до завершения предыдущей отклоняется; остановка отменяет
активный процесс, кандидата и завершающее запросы поколение.

Изменения не затрагивают Rust-алгоритм, веса и стартовый словарь. Снимки истории
сохраняют прежний формат. Цена сохранения рабочего профиля при reload — временное
удержание двух словарей; точный peak RSS на больших ресурсах здесь не измерялся.
Упаковка worker/ресурсов в portable launcher остаётся прежним явно описанным
ограничением, не объявлена исправленной этим ревью.

Проверки и их полный вывод:
[022-integration-review](../../rechprav/experiments/022-integration-review/report.md).
Тесты используют временные БД и отдельные localhost-серверы. Рабочая БД,
службы и пользовательский `first-plan.md` не менялись.
