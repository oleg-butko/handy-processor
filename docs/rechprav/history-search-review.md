# Ревью поиска истории

2026-09-26. Проверена реализация `d2698a1`: SQL-выборка, поиск по русскому
тексту, фильтр замен, пагинация, браузерное поведение и объяснения в карточке.

**P2 — медленный поиск блокировал сервер.** Для каждого исходного и итогового
текста SQLite вызывал JavaScript-функцию, которая всегда сворачивала пробелы и
вызывала `toLocaleLowerCase("ru-RU")`. На технической истории из 50 000 записей
запрос по двум полям занимал 858 мс; совместный поиск с фильтром — 809 мс.
Пока выполняется синхронный запрос, Node не обслуживает другие HTTP-запросы.

Исправление: обычное Unicode-приведение регистра через `toLowerCase()` и быстрый
поиск в строке. Схлопывание пробелов выполняется только при поиске фразы и лишь
для текстов с нестандартными пробелами или переносами, где простой поиск не
нашёл совпадения. На том же наборе запросы заняли 263 и 209 мс соответственно;
число найденных строк совпало. Это единичный замер на технических данных, без
попытки выдавать его за гарантию на любой базе.

Проверки корректности: более миллиона одиночных Unicode-символов дали одинаковый
результат при `toLowerCase()` и `toLocaleLowerCase("ru-RU")` в текущем Node;
регрессии поиска русских слов и фраз с переносами и повторными пробелами прошли.
Схема БД и сохранённые записи не менялись. Алгоритм выбора терминов не менялся.
Поиск всё ещё сканирует историю; при лимите в 1 млн записей время отдельно не
измерялось.
