# 014 — обратимые предложения из подтверждённых правок

2026-09-21. Протокол до реализации/измерений. Предыдущий этап013 не менял
план редактора: сначала события и предложения, затем накопление весов/UI.
Этот этап — отдельный offline-инструмент, исходный корректор и сервер не меняются.

JSONL schema_version=1: события correction с event_id, scope, before, after,
confirmed_asr и необязательным selection {byte_start,byte_end,replacement};
события retract с собственным id и target_event_id. Полные строки сохраняются.
Повтор одинакового event_id/содержимого идемпотентен; отличающееся содержимое
под тем же id — ошибка всего файла. Отмена ссылается только на предшествующую
correction; повтор отмены не воскрешает событие. Новое подтверждение с другим
id может снова поддержать предложение. Неверный журнал не создаёт output.

Автовыделение: минимальная замена 1–3 целых лексических слов на1–3 слова,
с побайтно сохранёнными краями. Чистые вставки/удаления, несколько участков,
защищённые токены, изменение форматирования вне span, неоднозначность — review.
При явном selection проверить границы UTF-8/слов и точную реконструкцию after.
Пунктуация/перенос не входят в alias. Нормализация/case-only без реальной замены
не порождают alias. Автовыделение консервативно отказывается при общем внутреннем
слове в меняющемся блоке; это может потребовать selection для сложной фразы.

Контекст: максимум один сосед слева и справа, только через горизонтальный пробел,
из before; оба соседа образуют один anchored pattern. Отсутствие соседа/перенос
не заменять догадкой. Target классифицируется по общему словарю и каноническим
формам активного пользовательского профиля: existing_user_term, dictionary_word,
unknown_word_candidate либо phrase. OOV не означает автоматически новый термин.

Сгруппировать предложение по scope+normalized source+canonical target+context.
Стабильный id, список активных evidence ids, число уникальных подтверждений.
Вес фиксирован: повтор подтверждения пока не изменяет boost. Пересчёт из журнала
после отмены; если поддержек больше нет, предложение исчезает. Отдельные пары,
контексты и scopes не объединять. Противоречивые цели отмечать для review.

Выход: audit/report + отдельная TOML-конфигурация предложений, disabled на уровне
прохода/набора/термина. Ничего в исходном пользовательском профиле/словаре не менять.
Это отдельный exact-проход, не неявное добавление aliases в общий edit-профиль.
С контекстом require_context=true, known_words=always/cap0, без контекста never;
положительный boost0 и source penalties отсутствуют. При принятии предложения
нужно явно включить проход/набор/нужный термин в отдельной копии. Коррекция ASR
не равна согласию на глобальное правило. Автоматическое принятие/UI не входят.

Эксперимент: зафиксировать synthetic события и отдельные новые строки до кода.
Сравнить disabled draft, явно принятые контекстные предложения, удалённый контекст,
дубликат события, независимое повторное подтверждение, отмену одного/последнего,
конфликт целей, другой scope. Оценить повтор известного окружения и новый контекст,
обычную речь и буквальные упоминания. Метрики не смешивать с real_asr.
Проверить действия с неверным журналом/selection, стабильные ids, provenance,
словарную классификацию, формы, бюджет, отказ перезаписи, порядок/отмены.

Rust runtime не меняется: добавить отдельный example и модуль offline-workbench,
его source fingerprints; все прежние тесты и шесть представительных прошлых
прогонов (013 edit/weighted, 012 source/context, 011 flat/family) побайтно.
Не копировать все169 старых комбинаций без изменения их корректора. Новые
принятые правила оценивать старым проверенным terms-benchmark. После результатов
не дописывать исключения/контексты под ошибки.
