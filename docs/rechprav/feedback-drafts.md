# Предложения настроек из редакторских исправлений

Offline-инструмент этапа 014 читает журнал событий и создаёт **выключенную**
конфигурацию отдельного exact-прохода. Рабочий профиль, словарь и редактор
не изменяются. Исправление распознавания и принятие правила — разные действия.

## Запуск

```bash
/home/user1/.local/bin/cargo build --manifest-path rechprav/Cargo.toml --release --locked --offline --example feedback_draft
rechprav/target/release/examples/feedback_draft rechprav/data/fixtures/feedback-drafts/events.jsonl --config rechprav/configs/terms-families.toml --scope technical --output-dir rechprav/artifacts/my-feedback-draft
```

Выходной каталог должен быть новым, родитель — существовать. Требуются ранее
подготовленные ресурсы указанного профиля. Он используется для словарной
проверки и определения уже известных терминов/форм; его правила не копируются
в черновик. Валидация журнала завершается до создания каталога.

- report.json: предложения, evidence ids, классификация, конфликты, разбор событий.
- proposals.toml: отдельная конфигурация, выключенная на уровнях прохода,
  набора и каждого термина.
- draft-manifest.json: хеши входа, опорного профиля, ресурсов, скомпилированных
  исходников и выходных файлов.

## События

Одна JSON-запись в строке, schema_version=1. Это новая схема инструмента;
иллюстративный example-event этапа 012 не является её совместимым API.

```json
{"schema_version":1,"kind":"correction","event_id":"edit-001","scope":"technical","before":"сняли свод памяти","after":"сняли слот памяти","confirmed_asr":true}
{"schema_version":1,"kind":"retract","event_id":"undo-001","target_event_id":"edit-001"}
```

confirmed_asr=false означает, что событие не используется для предложения.
Это сигнал редактора/пользователя, не автоматическая классификация намерения.
Для указания единственного участка доступно поле selection:

```json
{"byte_start":11,"byte_end":19,"replacement":"слот"}
```

Смещения относятся к исходным UTF-8 **байтам** строки before; byte_end исключается.
Подстановка обязана точно давать after. Повреждённые границы и несовпадающая
реконструкция — ошибка журнала. Существующее содержимое не перезаписывается.

Одинаковый event_id с семантически одинаковым содержимым дедуплицируется;
другая правка под тем же id — ошибка. Отмена ссылается только на предшествующую
correction. Повтор отмены допускается, но не восстанавливает событие.
Новое подтверждение с новым id может снова поддержать ту же пару. Предложения
полностью пересчитываются по активным событиям, без арифметического вычитания весов.

## Выделение пары и контекста

Поддерживаются 1–3 целых исходных слова и 1–3 выходных слова. Автовыделение
проверяет точное совпадение внешних частей before/after и минимальность участка.
Код/URL, смешанный регистр исходника, чистые вставки/удаления, изменение только
нормализации/регистра, несколько участков и неоднозначные правки остаются в review.
Изменение форматирования вне участка также не превращается в речевой alias.
Короткие русские слова допускаются, как в существующем терминологическом проходе.

Алгоритм намеренно консервативен: общее внутреннее слово внутри изменяемого
блока может означать несколько правок и требует явного selection. Selection
разрешает указать такую фразу целиком, но не отменяет проверки защищённых токенов,
границ и воспроизводимости. Форматирование/регистр неизменных краёв фразы не
должны расходиться с after. Профильные domain/ignore также блокируют предложение.
Причина needs_selection_or_review не означает, что исходное исправление неверно.

Контекст берётся из before: ближайшее слово слева и справа, только через
пробел/табуляцию/NBSP. Если доступны оба соседа, они образуют один обязательный
шаблон: сняли {term} памяти. Через пунктуацию/перенос сосед не подбирается.
Шаблоны не расширяются на синонимы, другой порядок или все падежи автоматически.

## Классификация и предложение

target_class проверяется в порядке:

1. existing_user_term — canonical или форма активной записи опорного профиля,
   включая уже заданную фразу. Сравнение по нормализованному ключу, регистр
   выхода остаётся таким, каким его указал пользователь.
2. phrase — новая многословная цель; membership каждого слова сохраняется отдельно.
3. dictionary_word — одно слово найдено в общем словаре.
4. unknown_word_candidate — одно слово отсутствует: кандидат в термины, но
   также возможны имя или опечатка. Словарь не изменяется автоматически.

Предложение группируется по scope, источнику, точной canonical и контексту.
ID стабилен при повторах/отмене части подтверждений; evidence ids отсортированы.
Вес фиксирован, число подтверждений само по себе не повышает boost.
Разные цели одного alias отмечаются как потенциальный конфликт даже при разных
контекстах: это консервативное предупреждение, а не анализ пересечения шаблонов.

Генерируемые правила: mode=exact, boost=0, max_known_distance=0; с контекстом
require_context=true и known_words=always. Без контекста known_words=never:
так из изолированного Нет звон не получается глобальная замена обычных слов.
Штрафы источнику и взвешенная дистанция не включаются. Известный термин в опорном
профиле не получает новый alias для всех своих форм: это отдельное предложение
для конкретного выхода и окружения.

## Принятие и отмена

Для локальной проверки можно создать отдельную копию proposals.toml и включить
её проход, набор и выбранные термины. Эксперимент делает это явно только в своих
артефактах. Никакая команда не устанавливает правила в рабочий сервер.

Отмена события меняет **следующий пересчитанный черновик**. Она не меняет старые
экспортированные копии и не отключает уже вручную установленные правила.
В 015 добавлен [реестр принятых предложений](feedback-registry.md): он исключает
отозванное правило из следующего active.toml. Привязка к работающему приложению
и обновление уже загруженного профиля ещё не реализованы.
Смешивание разных scope не выполняется; выбор домена остаётся явным.

Ограничения: 10 000 событий, 64 MiB входного файла CLI, 4096 байт before/after,
128 лексических токенов на строку, до 512 предложений. Неизвестные JSON-поля
отклоняются. Активные correction в report считаются по всему журналу, включая
другие scopes и неподтверждённые события; применимость указана в audit.
Структурно неверные события не скрываются отменой или выбором другого scope.
