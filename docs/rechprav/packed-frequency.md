# Упакованные частоты `.rpf`, версия 1

В опыте 005 меняется только хранение частот. Нормализация, максимум при
совпадении ключей е/ё, значения `f64` и формулы B2 остаются прежними. TSV
остаётся исходным ресурсом и контрольной реализацией. Сборка выполняется заранее:

```bash
rechprav/target/release/rechprav build-frequency rechprav/artifacts/opencorpora-wordfreq/frequency.tsv --output rechprav/artifacts/opencorpora-wordfreq/frequency.rpf
```

Команда проверяет каждое значение по битам после упаковки и до записи файла.
Выход должен быть новым; неправильный вход не создаёт файл. `--strict-yo`
должен совпадать с режимом последующего TOML. Расширение `.rpf` в
`[frequency].path` выбирает готовую таблицу; остальные пути читаются как TSV.
Пример: `rechprav/configs/opencorpora-packed-frequency-b2.toml`.

## Формат

Все целые числа little-endian; нет native structs, указателей, unsafe или mmap.
Заголовок занимает 96 байт:

| Смещение | Содержимое |
|---:|---|
| 0 | 8 байт `RCHFQ001`, включая версию |
| 8 | strict_yo: 0 или 1 |
| 9 | 7 нулевых резервных байт |
| 16 | число ключей, u64 |
| 24 | размер блока ключей, u64 |
| 32 | SHA256 исходного TSV, 32 байта |
| 64 | SHA256 заголовка `[0..64)` и содержимого `[96..end)`, 32 байта |

После заголовка идут записи по 16 байт: смещение ключа в блоке `u32`,
длина в байтах `u16`, два нуля, точные IEEE-754 биты частоты `u64`.
Затем идут UTF-8 ключи подряд, без разделителей, строго по возрастанию.
Лимиты версии: число ключей и размер блока не больше `u32::MAX`;
каждый ключ содержит 1–128 строчных русских букв.

При загрузке проверяются точная длина файла, арифметика размеров, checksum,
резервные поля, непрерывность смещений, UTF-8, алфавит и нормализация е/ё,
строгий порядок и уникальность ключей, конечность частоты и диапазон 0..1e9.
Лишние байты и несовпадение режима е/ё запрещены. Нулевое значение отличается
от отсутствующего; отрицательный ноль сохраняется, как в исходном TSV parser.

После проверки таблица хранится в одном `Vec<u8>`; lookup — бинарный поиск.
Загрузчик не создаёт отдельные строки и BTreeMap. Источник SHA256 нужен для
прослеживаемости, внутренний checksum — для обнаружения повреждений; это
не подпись доверенного автора. Общий загрузчик отдельно вычисляет SHA256 всего
ресурса для manifest, как и для словаря. Проверки не отключаются ради скорости.

Измерения, ограничения и решение: [отчёт 005](../../rechprav/experiments/005-loading/report.md).
