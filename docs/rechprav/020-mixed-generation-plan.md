# 020: manual edit + точные принятые aliases

Дата: 2026-09-22. Предыдущие результаты: 017, публикация/reader 018–019.

Гипотеза: отдельная политика `generation = "exact"` у выученного правила позволит
сохранить ручной edit-поиск, не расширяя принятый alias автоматически. По умолчанию
`inherit`: существующие конфиги работают как прежде. Exact сравнивает нормализованные
слова с сохранением их границ, до weighted/edit веток; формы наследуют политику.
Веса, gates, penalties, контекст, budget и ранжирование общие, без новых порогов.
Композитор всегда выставляет generated=exact, снимает только запрет global edit.
Свободные context cues всё ещё не поддержаны.

До изменения runtime сохранить предыдущий binary в ignored artifacts. Заморозить
корпус: прежние 20 строк 017 + новые технические controls, включая подтверждённый
трёхсловный alias ПНЗ и его слитные/контекстные варианты. Эти варианты считать
положительными gold, даже если exact их пропустит. Это dev/стресс-контроль, не
независимая оценка настоящего ASR. Весами/порогами по нему не оптимизировать.

Сравнения: manual exact, composed exact, manual edit, mixed, weighted mixed;
diagnostic unpinned снимает exact у generated (невалидный для публикации артефакт,
показывающий опасность наследования). Ablations: выключатели, веса владельца/нового
термина, равные конкуренты/предпочтение владельца, known gate, exclusions, undo,
duplicate и source penalty. Проверить не только gold, но отсутствие generated
кандидатов для неперечисленных aliases и прежнее поведение ручных definitions.

Проверки совместимости: старые конфиги без generation — побайтно прежние predictions
на 22 профилях 017, включая manual-edit; weighted контроль 013. Полный Rust suite.
Fingerprint runtime изменится: старые reviews должны стать stale, старые publication
bundles отклоняться. Построить новые reviews для тестовых profiles; не править
исторические snapshots и не отключать guard. Publication SIGKILL suite и reader
проверить с новым экспортом и отдельной проверкой отказа старого экспорта.

Выбор решения по поведению/регрессиям и явным FP/FN. Не объявлять mixed лучшим
корректором для реального ASR. Runtime-проект HandyProcessor пока не подключать.
